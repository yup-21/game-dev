# 听风五式：当前战斗内核

默认入口仍是 battle.tscn → scripts/battle_view.gd → BattleModel。原型机制已拆分迁入现有工程，没有把单体 TingfengEngine 作为第二份状态接到旧状态机旁边。旧五阶段源码留在原 Creator 工作区的存档，本仓库仅收录当前 Demo。

所有规则对象均为 RefCounted，不访问 SceneTree。仅 UI 使用帧时间播放动画；操作确认不推进战斗时间，也不产生新资源。UI/AI 只拿快照和合法请求。Godot 本身允许调试代码访问对象，此处隔离的是业务调用路径，不宣称语言级的内存安全沙箱。

## 行动与时间

`TIMELINE → ACTION_START(自动) → ACTION ↔ CLASH → ACTION_END(自动) → TIMELINE`。UI 中不会要求手动经过布势、交锋、收势。结束行动减去集气阈值并保留溢出；无人就绪时跳到最近的集气完成、状态到期或护体到期事件。

气血、内息和护体使用 10000 整数单位；时间恢复使用整数余数，分次推进不会丢失精度。属性的集气速度与资源恢复分别计算。同速开局用明确先手，后续稳定排序保留可复现性；属性与被动通过 reset options 注入。

```gdscript
model.reset(2026, 0, "tingfeng", {
    "attributes": {0: {"AGI": 20}, 1: {"AGI": 10}},
    "passives": {0: {"insight": 1}, 1: {"conceal": 0}}
})
```

双方各有12实例、初始5手牌和3内息。首次起势不补资源；以后自己的起势替换手牌，但不额外发3内息。护体100 tick、露隙/明牌150 tick。ACTION、CLASH、等待输入与动画均不推进全局 tick。

## 提交与挂起

1. 先严格核验请求字段类型，再检查 battle_id、版本、已消费编号、UID别名、权限和表现锁。
2. 查询声明用法、目标、路径、条件、费用；完整校验失败不改变仿真、日志或 RNG。
3. 控制器分配缺失的操作编号并提交一次支付；发动牌先进入 resolving。
4. 非攻击直接执行效果；攻击建立根攻击，写入连携奖励并将优先权交给守方。
5. 双方可出一张合法响应或 Pass。每方2张、总4张；两次连续Pass或第4张后LIFO，不允许栈结算中重入新窗口。
6. 按最终站位检查锁定覆盖，中断／落空不返费。HIT、HP_DAMAGED 独立；死亡停止后续派生，并统一清理挂起牌和窗口。
7. 返回事件，UI自行播放。唯一版本和票据阻止旧回调影响新局。

当前原型保留明确的 Pass 交权，无手牌时 Pass 合法。只有拥有响应权的人能响应；完整行动权不因响应转移。

## 效果和扩展

五式使用伤害、护体、移动、内息、待决增减伤、扩区、截势、迎锋、中断、状态与命中/落空子效果。公共接口还保留气血费用、有限条件增伤、强制位移、抽弃牌。强制位移逐格检查障碍和占位，阻挡只终止位移，不吞掉后续效果。

成本快照 `quoted_cost` 与真正支付共用 CostResolver；低血量条件在费用已付后、命中伤害前检查。配置不允许脚本路径或代码执行。通用条件只接受登记的有限字段，未知效果与坏配置不会在付款后才报错。

连携历史只记录主动攻击牌的已完成出招（含命中、中断等结果）；普通移动、护体、反应不打断探锋追风。中断招式不能贡献有效前招。每次 ACTION 每种连携最多一次。

Hook 注册只发生在代码中。Validator/Modifier 得到拷贝，返回允许与数值；Trigger 只生成声明式效果列表。EventLog 只记录，执行在独立同步队列中。默认每根行动同一 Hook 一次，支持按拥有者自身行动间隔限次；嵌套分支同样计入32条上限。重复触发、无效效果和超限均记录诊断，不递归调用 submit。敌我按相同流程处理。

虚招、陷阱、内功、其他武学可继续通过使用时机、公共效果、条件与注册 Hook 扩展。当前没有启用额外门派系统或把历史40牌的五阶段配置自动当作自由行动配置。

## 信息和验证

未知敌手牌不包含 UID 或定义；对手的抽牌堆、剩余牌序不进入决策上下文。一级观势的换手刷新按手牌批次去重，重绘不会多揭牌；离手立即忘记该 UID 的当前手牌知识。攻击和响应发动后成为公开事实，相关牌名才可显示。
