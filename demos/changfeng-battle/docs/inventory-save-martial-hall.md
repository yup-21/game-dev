# 行囊装备、消耗品、存档与武学演武堂

## 系统边界

这套系统以 **Demo C → PR #14（统一状态与成长）** 为基础，不额外实现一套战斗规则。

### 物品与包裹

`data/items.json` 统一注册装备、药品、材料、剧情道具；`InventorySystem` 实现：

- 九个实际装备部位：武器、副手、头部、衣甲、双手护腕、腰带、鞋履、饰品 1/2。
- 按物品 `stack_limit` 分堆；按 `capacity` 统计占用背包格数；按 `max_weight` 限制负重。
- 同 ID 物品可以占据多个堆叠格，装备时从包裹扣 1，卸下时原子性归还背包。
- 更换装备先计算新背包，只有整体合法才真正替换；容量、负重不足、双手武器与副手冲突时，原有装备不被吞掉。
- 装备词条直接进入 `AttributeModifierPipeline`：与 Buff/重伤/武学境界共用 flat → percent → clamp 顺序，永久基础属性不被覆盖。
- 三种实际消耗品：金疮药（气血恢复）、回气丸（内息恢复）、通脉膏（解除一层暗伤）。战斗中通过新增 `USE_ITEM` 合法行动提交，由 `CombatRules` 校验并由原 `CombatResolver` 执行；仅当前 ACTION 可用，每次自身行动最多使用一次，不能在 CLASH 中额外出手。
- 战斗外仅通脉膏可治疗存在的暗伤；疗伤、包裹改动保存在 `GameSession` 中。物品使用和存档不公开隐藏寿元数值。
- 正线镖头剧情会把《太虚引气残篇》作为不可装备／不可消耗的任务物品实际放入包裹。

`inventory.tscn` 是可操作的装备／包裹界面：物品分类、18 格分页、物品详情、九部位装备、装备/卸下、消耗品使用、负重与格数、武学/存档/返回导航。默认 18 格 / 45 负重，可按角色配置扩大。

### 武学演武堂

`martial_hall.tscn` 展示武学目录、当前境界、五重突破路线、所需熟练度、招式介绍、两条互斥武意分支、四维基础属性修炼和存档/装备导航。

`data/martial_catalog.json` 声明武学突破后的真实属性效果，而不仅是 UI 文案。第 2～5 重逐步解锁内息恢复、破招、耗气、集气的直接数值加成。太虚在第 4 重可从「绵绵不绝」与「势如奔雷」中选择一种武意，选中后实时影响下次战斗计算。未习得的武学只展示图鉴，不能点击绕过解锁。

原 `MartialProgression` 继续保存 XP/rank/traits；新目录专门保存效果定义，调用时只读取已通过校验的职业成长记录。

### 存档系统

`SaveSystem` 提供本地三档位，保存位置为 Godot 的 `user://saves/slot_01.json`、`slot_02.json`、`slot_03.json`。

- `version: 1`，包含数据与规范化 JSON 的 SHA-256 摘要；读档时拒绝版本不符、摘要不符、非法装备物品、非法成长记录以及不完整的数据。
- 写入先 `.tmp`，旧档保留 `.bak`，再原子改名提交；失败尽量恢复旧档，避免直接覆盖已存在的正文。
- 保存剧情标记、人物永久属性点、武功熟练度／境界／武意、角色永久状态、装备和背包数量、当前剧情检查点。
- 战斗中的行动时间轴、响应栈、手牌临时 UID 不序列化，**仅允许剧情／战后／序章结束存档**。战斗内的消耗品使用在战斗结束写回；如果重开战斗会从战前保存的状态重新开始。
- 读档恢复剧情阶段／章节、角色与物品记录，兼容主菜单、剧情参悟及战后结算的安全恢复。
- 新游戏不会覆盖旧档；三档管理界面支持存、读、删、损坏提示和返回。F5 可进入存档管理。

### 入口

- 主菜单：存档与继续。
- 序章场景：F5。
- 参悟残篇：行囊装备 / 武学修炼 / 存档。
- 战后结算：行囊装备 / 武学修炼 / 存档。
- 行囊与武学页：互相切换，按 Esc 返回先前场景，不清除当前剧情或成长记录。

## 验证命令

```bash
godot --headless --path demos/changfeng-battle --script res://checks/test_save_inventory_martial.gd
```

或者 Windows 项目目录内：
```powershell
.\checks\verify.ps1 -Stage InventorySave
.\checks\verify.ps1 -Stage All
```

测试包括堆叠和负重、换装库存守恒、装备修正、战斗内合法使用药品与每回合次数限制、剧情物品获取、战斗物品消耗写回、战斗外疗伤、三档存档的实际文件读写、损坏文件拒绝、武意互斥、境界效果和三张 UI 场景资源检查。

**本分支的提交环境没有 Godot 可执行文件。测试尚需 GitHub Actions 或本地实际执行，不能将源码检查写为已通过。**

## 本阶段刻意不做的功能

自动存档战斗中的整个 CTB/牌堆状态、装备随机词条或强化、打造台、仓库存取、商店买卖、物品交易、开放世界的长线商队负重。其数据模型可以逐步在现有物品 ID/堆叠/装备记录上扩展。
