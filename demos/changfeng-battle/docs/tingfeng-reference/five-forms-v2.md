# 《长风浮生录》听风五式 · Godot 4 战斗原型 V2

> 本项目是基于上一版「听风十二势」**真实源码增量修改**得到的独立 Godot 4.x 原型，未访问或改动用户另外的 Godot 正式工程。

## 核心压缩结果

原版 12 个不同卡牌定义 + 16 张/人的牌组，压缩为 **5 个卡牌定义 / 12 个使用方式 / 12 张/人的镜像牌组**，同时维持可用于验证连携、响应、闪避、迎击、破招与信息博弈的规则。每次持有同一个卡牌实例可选择一种合法用法，使用后整张牌进入弃牌区，**不能同牌多用**。

| 五式 | 主行动用法 | 连锁响应用法 | 验证重点 |
| --- | --- | --- | --- |
| **探锋式** | 探锋·试探（1气/2伤） / 探锋·追风（1气/2伤） | — | 同一式多用法、起手→追风 +1 伤害连携 |
| **断岳式** | 断岳·重斩（3气/5伤，威胁高，落空露隙） / 断岳·照胆（2气/3伤，命中明牌；利用露隙 +2） | — | 重击风险、派生照胆、负面完全曝光 |
| **游身式** | 游身·踏雪（1气/移动 ≤2 格） | 游身·避锋（1气/移动 ≤1 格） | 战棋空间、落空、主动/应变一牌两用 |
| **化劲式** | 化劲·护元（1气/+3 护体） | 化劲·卸劲（1气/本击 -3伤）；化劲·迎锋（2气/判定中断） | 防守选择：护体、减伤、主动迎击 |
| **变锋式** | — | 变锋·追击（进攻方响应1气/扩展攻击区域）；变锋·截势（攻/守方响应1气/取消敌方一层响应） | 多层 Chain、反制与反反制 |

**注意：** 本轮没有额外新增完整武学体系、架势条、回合行动点、实时按键弹反，连锁仍限定每方最多 2 张、总共最多 4 张。动作可选操作在自己的自由 ACTION 中执行；CLASH 连锁期间全球战斗时间停表。

## 情报：改为双向角色被动

取消主动卡牌《观势式》《藏锋式》。在场景左侧四个下拉框分别调整我方/敌方观势、藏锋（0/1/2级），点击「应用被动等级并重新开战」，即可直接对比：

- **观势 0**：正常看到敌人手牌数量和高威胁「危」（仅表示对手手里有危险牌，不预测行动）；**观势 1**：敌人换手后自动识别其一张未知牌；**观势 2**：自动识别全部当次手牌。
- **藏锋 0**：不隐藏危险提示；**藏锋 1/2**：掩盖危险预警为「？」且对抗不高于自身等级的观势。观势等级 **严格大于** 对方藏锋等级才生效，同级时藏锋获胜。
- **明牌（负面状态）**：由断岳式·照胆实际命中后产生，持续150逻辑 tick，覆盖任何级别的藏锋；持续期间新抽取牌也暴露。
- **情报记忆**：曾经见过的**仍在对方手牌中**的卡 UID 保持已知；牌离开手牌立即忘记其当前手牌身份。对手状态改变不凭空抹掉已知事实。
- **敌我对等**：双方具备同样的被动结构。AI 只能读取自身视角的 `view("enemy")`，不能依靠隐藏真值预测玩家手牌。

为便于测试，原型用 0～2级配置模拟被动学习；**尚未开发游戏世界中的被动技能学习与角色存档系统**。

## 保留的引擎框架

1. `TIMELINE`：集气速度决定何时获得完整行动，阈值 10000；双方内息按**全局时间**恢复，不随自己的行动次数额外获得固定回气。
2. `ACTION_START` → `ACTION` → `ACTION_END`：无需逐一手动切换布势/交锋/收势。行动期间可穿插移动、出招和运功。
3. `CLASH`：每次攻击单独触发交锋；防御方先响应，双方交替追加，逆序结算；可变锋追击、游身闪避、卸劲与截势。
4. `Combo`：探锋的 `probe` → `follow`（同一角色 ACTION、已结算前一攻击，中途非攻击动作不打断）；露隙目标被断岳·照胆命中 +2 并消耗露隙。
5. **统一行动与效果入口**：UI/AI提交包含 `card_uid + usage_id` 的合法 ActionRequest，校验失败零副作用；Hook 只能提交声明式效果。

## 运行

用 **Godot 4.3+** 导入本文件夹的 `project.godot` 并运行主场景 `main.tscn`。屏幕左侧棋盘、手牌、观势/藏锋等级，右侧按「式」折叠操作，可展开选择分支/响应方式。按 2026 固定随机种子重开。

定向测试（需 Godot 已安装）：

```bash
godot --headless --path . --script res://tests/test_engine.gd
```

`tests/test_engine.gd` 验证卡牌定义数、分支用法、CTB与内息独立、连携、三层 LIFO、空间闪避/追击、迎锋、明牌压过藏锋和被动等级对抗、Hook、非法请求等。

**验证状态：** 已做 JSON 结构与源代码静态检查；本构建环境没有 Godot 可执行文件，尚不能声明 GDScript 编译与场景实际运行通过。

## 对接你现有正式项目

- 将本包作为独立测试模式或演示分支合入，不要再建第二套权威 BattleState。
- 优先迁移五个 CardDefinition 和 `usages` 多用途逻辑，再迁移被动情报逻辑；与现有 CombatState、请求去重、事件日志和 UI 实现做映射。
- 卡牌配置集中在 `data/tingfeng_cards.json`；运行时真实信息在 `TingfengEngine` 中，玩家/AI 只能消费 `view(viewer_id)` 对应权限投影。
- 本测试工程为两名角色、7×5 棋盘的最小实现；不代表正式地图规格。
