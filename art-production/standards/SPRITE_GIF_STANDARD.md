# 精灵图生成规范 B：直接生成逐动作 GIF

本路线用于**让动画生成模型直接输出 GIF 动画**：每个动作独立生成一张 GIF，不以 5×5 Sprite Sheet 为原始输入。与[规范 A：5×5 图集](SPRITE_SHEET_5X5_STANDARD.md)并列，由任务指定。

## 输入与动作规划

- 每名角色共享同一获准身份设定、装备/武器契约、右向侧视参考、自然身高和逻辑地面根点 O；不跨动作更换脸型、服装、武器数或镜头。
- 按动作独立分镜，确定实际帧数范围、起手/发力/收势、运动方向、循环与建议时长。**一个 GIF 只包含一个 action_id**；12 组动作允许按需逐次制作和导入，不要求一次生成完毕。
- 对生成模型发送**短的单动作动画提示词**，明确连续运动、同一人物、固定视角、完整武器与身体、支撑脚/重心和循环或终态。**不发送 5×5、25 格或 cell_index 指令**。
- 输入 GIF 的实际分辨率、帧数、时间和是否有透明背景均以文件真实数据为准；生成模型不能精确控制尺寸或 Alpha 时，在后处理阶段解决，不把原稿未达标准作为编辑的阻断条件。

## 生成和后处理

1. 为 idle、walk、run 等循环动作生成首尾可衔接的连续动画；攻击、技能、闪避、格挡、受击等非循环动作包含明确阶段并恢复待机兼容姿势；defeat 保留倒地终态。
2. 原始 GIF 保存完整文件，不拆成伪造的 5×5 源图；记录 action_id、生成参考、实际画布、真实帧数、各帧毫秒时长和循环标记。
3. 使用 **V3 逐帧工作台** 解码 GIF，按需要清边、抠图、补透明、编辑帧顺序、等比调整大小与脚点；保留真实动画节奏。GIF 的索引透明和调色板量化只是来源格式，最终帧输出为 RGBA。
4. 以该角色统一的 **328×256** 或 **384×288** 画布标准化最终 PNG 帧；跨动作同一自然身高、同一 O，四边至少 **8px 真透明边距**，不拉伸，不让人物和剑溢出。源图若确实缺失肢体、武器或关键动作，返回对应动作重制。
5. 逐动作实速预览，检查身份漂移、闪烁、重心、脚滑、武器轨迹、首尾循环和收势；修改后的帧时长显式写入最终原生动画。

## 交付

- 每个动作交付一张原始 GIF、处理后的透明帧序列、真实帧时长以及必要的审核说明。**不要求 C×R 网格、25 格映射或 Sheet 整图**。
- 经导入器将指定动作**增量更新至同一角色的一份 SpriteFrames.tres**；只替换本次动作，保留其余动作，AnimationProfile 维护统一脚点/比例。
- 最终在 Godot 原生 SpriteFrames/角色场景播放验收。按任务逐组交付可以标记阶段性 candidate，完整角色再验收 12 动作。
- 若实际来源是先生成 5×5 图集、再抽帧编码 GIF，应记录为 **规范 A 衍生 GIF**；两条生产路线按**原始生成来源**区分，而非仅凭文件扩展名。
