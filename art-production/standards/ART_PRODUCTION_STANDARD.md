# 《长风浮生录》美术与动画制作规范 V1

**适用范围：整个游戏，而非某个 Demo 场景。** 本规范同时约束角色、地图、剧情演出与战斗表现。Godot 原生 Resource 是游戏内容入口；源图和制作过程可以保留在概念素材区，但不能作为第二套运行时数据格式。

## 1. 美术方向与资产状态

- 中国武侠手绘、精细但简洁的轮廓、克制的水墨肌理和真实材质；HD-2D 描述固定镜头、纵深、前后景及遮挡，不强制像素画，也不使用 3D 棋盘叠图。
- 角色立绘与战斗小人属于同一身份设计：发型、服装配色、武器及标志性配件不得无故变化。
- 地图使用可阅读的地面空间，中央可行走区域与场景装饰分离；效果不得遮住重要站位、交锋目标或 CTB。
- 素材版本管理只区分 `candidate` 与 `in_use`，前者可有多份，后者由当前原生 Resource 绑定决定。`concept`/`preview` 是制作用途描述，视觉审核结果记录在工作单中，**不另建管理状态**；运行可加载不等于图像和动作质量已通过。
- 候选记录至少保留实际提示词和目标原生 Resource；可另保留来源/权属等已知信息，不强制补造模型、seed 或审批链。**未完成目标素材的人工验收不可替换当前运行绑定**；离线工作单不是游戏内容入口。
- **绘图提示词保持简短且确定**：Agent 根据 Skill 与角色设定，先决定素材类别、具体造型、动作、尺寸档位、网格、根点及实际值；调用生图模型时只发送**已完全展开、没有备选分支的短提示词**和获准参考图。高个规格由 Agent 根据身高与动作占用选定，不让生图模型判断；世界移动计划和运行时视觉偏移不放进绘图提示词。格子测量、Alpha 验收、脚点/动作检查和运行时配置留在工具／Resource，不复制整份规范或长负面词表给绘图模型。

## 1.1 Godot 导入路径与文件名

导入素材统一按**类型 → 角色/场景/技能 ID → 功能**组织，不按日期或制作批次分类。游戏目录不区分候选与使用中；文件名不重复所属 ID。完整路径、扩展名和默认绑定规则参见 [`assets/imported/README.md`](../../demos/changfeng-battle/assets/imported/README.md)。

- 默认立绘 `portraits/portrait.png`、动作 `sprites/atlas.png`、技能特效 `vfx/<actor-id>/<skill-id>/atlas.png`；场景使用 `background/ground/foreground/weather/story_preview`，UI 使用功能名。
- 手动指定 Resource 优先；仅空绑定按精确文件名查找。缺失必需素材直接报错，重复格式视为歧义；可选图层允许为空，不自动选择 `_vNN` 或占位。
- 候选区保留完整原文件名和多个版本；导入器只规范化导入副本，正式 `in-use` 镜像与实际 Resource 引用一一对应。
- **每张候选图也有独立 Godot `.tres`**：`data/art_candidates/` 按候选的类型／角色／动作及源版本组织 `WuxiaArtCandidateDefinition`，指向仓库中的 `art-production/candidates/` 源图并记录实际像素尺寸、声明网格和比例参数。候选 `.tres` 不进入 Content Manifest、不绑定运行时；只有显式导入时才将配置校验、转换为正式 `.tres`。不生成第二套 JSON 运行时定义。

## 2. 场景制作合同

**城镇、大地图及街区生成**：统一采用 [城镇与大地图比例尺生产规范](TOWN_MAP_SCALE_PRODUCTION.md)。DNF 式紧凑街区是本项目建议的空间密度参考，并非要求复制其场景素材或精确数值。当前剧情管线以 1600×1000 单屏街区分区制作；大型城市通过多个街区和区域拓扑呈现，不能把超大图缩小到一屏。

- 以 **1600×1000 的 16:10 逻辑画面**做基础设计；同时检查 1440×900 窗口，不能依赖单张图天然填满所有裁剪尺寸。
- 每张正式场景的交付包包含 `background`（远景）、`ground`（可站立地面）、`foreground`（可遮挡主体）、可选 `weather`/光照遮罩。所有图层采用相同画布原点、尺寸和透明通道；保留可编辑母版。单张概念图不等于分层交付。
- 战斗地图附带 Godot 原生 `WuxiaMapDefinition` / `WuxiaGridMapDefinition` 的地面、障碍、出生点、剧情标记；剧情场景挂到 `WuxiaChapterSceneDefinition.scene_art`；必需背景及已声明的分层缺失或引用错误必须在加载／导入预检中报错，不用其他背景隐式代替。角色脚点与地图可行走区域在同一坐标空间，绝不根据 PNG 颜色推断碰撞。
- 固定摄像机比例、地平线和人物脚点参照；重要道具及前景遮挡另建 `Node2D` 层，避免贴死在背景而无法正确穿行。
- 雨、雾、流水、灯光和落叶均为可关闭的独立表现层；低性能档关闭后不影响路径、LOS 或脚点。
- 验收：六人可站立区足够清楚，路径/碰撞与画面一致，前景遮挡正确，分辨率截图和真实 GUI 试玩通过。

## 2.1 统一战斗长度与原画比例尺（强制）

唯一常量：`demos/changfeng-battle/scripts/combat_scale.gd`。本条规格覆盖剧情与战斗角色、地图、碰撞及卡牌距离，不得在各系统重复维护另一套“每格多少像素”。

| 项目 | 冻结值 | 解释 |
| --- | --- | --- |
| 战斗长度单位 | **1 单位 = 80 世界像素** | 地图脚点与原生 2D 场景坐标系；世界像素不是显示器物理像素 |
| 普通人物视觉高度（当前运行时） | **2.5 单位 = 200 世界像素** | 现有播放器按待机 Alpha 轮廓自动适配的兼容行为；不等于新源图的设定身高 |
| 角色地面占位 | **半径 0.3 单位 = 24 世界像素** | 圆形地面碰撞和自由移动／攻击边缘距离，独立于衣袖和刀剑的视觉宽度 |
| 背景画布 | 原图和逻辑坐标以相同画布原点绘制 | 如 1600×1000 原图，坐标(800,500)对应世界(800,500)，不得私自二次拉伸 |
| 普通角色 Sprite 单格 | **328×256 源像素（宽×高）** | Sheet 宽 `328×列数`，高 `256×行数` |
| 高个角色 Sprite 单格 | **384×288 源像素（宽×高）** | Sheet 宽 `384×列数`，高 `288×行数`；同角色全动作一致 |
| 新角色源图身高 | **1 米 = 100 源像素** | 从脚底地线到自然站姿头顶；按角色设定 `round(height_m × 100)`，范围 **100–220px（1.0–2.2m）** |
| 历史 Atlas | 现存 256×256 / 6×4 等 | 仅为兼容存量 Resource；不作为新图的格子默认值 |

**新角色源图制作合同（两档）：** 角色设定必须先给出身高 `height_m`；全部 12 组战斗动作的**人物自然站姿高度**统一为 `round(height_m × 100)` 源像素（例如 1.75m→175px，2.10m→210px），不得随动作变化、镜头推进而放大缩小。这里的人物身高从地面承重脚底到自然头顶测量，**不包括举高的武器、跳跃位移或飘起的衣摆**；它们仍必须完整落在本角色选定的单格内。普通档 **328×256**，高个档 **384×288**（2.0–2.2m 或举剑、外伸姿势超出普通档时优先选择）；同一角色所有动作和独立 Clip Atlas 必须使用同一已选 **W×H** 格，单次 Sheet 宽高为 `W×C`/`H×R`，C/R 和有效帧数 N 由分镜决定。格子四边**至少 8px 真透明边距**，优先留出约 16px；角色、武器、衣袖或根运动超过格子时立即返工，不得裁切、逐帧缩小或悄悄扩大标准格。普通档容纳 220px 站姿只剩 36px 竖向余量；高个档也仅余 68px，不能保证举剑姿势必然容纳。两档均不够时须记录整角色专用规格并重新制作，不作为默认回退。

**贴图坐标约束：** AI 生成／修图时维持固定侧面镜头、同一地面逻辑根点 O（待机骨盆地面投影、+x 向右、+y 向下）、固定脚点及源像素比例；所有格使用同一个相对 O 的像素坐标。禁止逐帧按 Alpha 框居中或改变人物身高。真实承重脚必须与地线对应，不能用衣摆或剑尖替代；动作可改变局部姿态，但**整人前冲/后退位移不烘焙进精灵图**，应独立记录世界移动计划并在游戏控制层实现。当前 Clip 的 `root_offsets` 只移动 Sprite2D，普通非循环动作末帧必须归零，不能拿它冒充世界移动。

**源图像素与运行时世界像素是两个合同：** 新增的 `100 源像素/米` 与两档 **328×256／384×288** 是**制作及验收标准**，不改变当前 `combat_scale.gd` 的 80 世界像素/战斗单位、24px 地面碰撞半径或攻击距离。现有 `WuxiaActorAnimationProfile` 默认 `auto_fit_height=true`，仍会把普通角色待机轮廓归一到 **200 世界像素**；因此**仅更新美术规范不能让游戏中 1.75m 人物自动显示为 175 世界像素**。后续按角色真实身高呈现时须同步迁移正式 Resource、导入器及世界视觉比例配置并做实机验证；未完成迁移不得声称游戏内按米等比例。候选 Resource 当前 `display_scale()`、导入预检中针对 200px 的限制也是存量行为，不可拿它们验证新源图的身高合同。若不同动作的实际人物比例不一致，回到制作阶段统一，不能以每帧显示缩放掩盖。

**地图比例约束：** `WuxiaMapDefinition`／`WuxiaGridMapDefinition` 标注 `pixels_per_unit=80`，不符合全局尺度的资源将拒绝加载；分层背景同画布同原点。15×10 `MapBake.step` 仅是兼容 GRID 的地形索引采样密度，既不是世界长度单位，也不是角色身高比例。非正方形格不可能在屏幕上代表两个方向相等的物理距离：FREE 使用真实二维欧氏路径与单位换算；GRID 保留既有离散曼哈顿格数玩法，不再把格宽当成 FREE 的距离单位。

**改动边界：** 视觉比例不能自动更改攻击距离；规则卡中的“移动 2 / 射程 1”分别是逻辑距离单位，FREE 转换为 160px / 80px，攻击以双方 24px 地面半径的表面间隙判断。以后角色体型差异必须改成显式地面占位/可见高度定义，不能通过临时修改 Sprite2D.scale 间接影响判定。

## 3. 角色制作合同

- 先冻结一张身份设定板：正/背/左右轮廓、主色/辅色、角色自己的武器契约（允许徒手，注明类型/件数/持手/握法）、脚底基点、动作态度。立绘、故事姿态、战斗 Atlas 用同一设定；不得把某个角色的单剑设定作为全项目通用默认值。
- 立绘为独立透明 PNG/WebP；动作图要求真实 Alpha、统一色彩和明确的脚底基点，禁用白底 JPEG 当作已批准图集。
- 新角色每格**按角色选定普通档 328×256 或高个档 384×288**，但**不固定 6×4，不强制每动作一张 Sprite Sheet**；一个 Atlas 可容纳一组或多组动作，各动作保留有序绝对帧索引与真实帧数。图集宽度须为选定 W 的整数倍，高度须为选定 H 的整数倍，角色和武器均不得越格。历史的 256×256 / 6×4 是合法存量格式，不作为新图默认回退。运行时动作帧范围由 `WuxiaActorAnimationProfile` 定义。
- **新美术生产必需 12 组**：`idle` 待机、`walk` 行走、`run` 跑步、**基于角色武器契约的四套攻击变体**、`skill` 技能、`evade` 闪避、`guard` 格挡、`hit` 受击、`defeat` 倒地。单剑角色可参考直刺/下劈/横斩/蓄力重击；其他武器类型及徒手角色应自行设计适配的四套打击方式和语义 ID。每个动作先独立分镜并按复杂度选择帧数，**AI 每次生成一张包含连续多帧的动作 Sheet**，再由程序机械拆格/验收/装配。
- **当前 Godot 运行时支持 12 组动作 ID**：`idle`、`walk`、`run`、`attack1`、`attack2`、`attack3`、`attack4`、`skill`、`evade`、`guard`、`hit`、`defeat`。技能通过配置选择一个指定的攻击动作或 `skill` 动作，并可绑定单独 VFX 及有效帧 Cue；连携由动作与时间轴配置编排，不要求额外的 `combo` 图集。存量 Profile 中的 `move`、`attack`、`combo` 仅在显式配置时继续使用；不能把旧动作名作为缺失新动作的静默回退，也不能固定武器或攻击方式。非循环动作必须有清楚起手/发力/收势，除倒地终止态外恢复到统一待机兼容姿势；恢复姿势不能导致世界位置瞬移回起点。`idle/walk/run` 必须各自循环闭合，`defeat` 结束应停留在倒地姿态。
- 朝向要求最终实现前、后、左、右一致的轮廓与脚点。目前播放器对左右使用镜像，上下仍沿用最后水平朝向；在完整方向动作接入前，不能把角色标为四方向最终批准。
- 游戏规则时序由 `BattleActionTimeline` 记录语义窗口；动画帧只负责表现，不能写 HP、Qi、CTB、背包或响应权。

### 3.1 精灵图逐帧质量闸门（强制执行）

角色动画按 [精灵动画生产与验收合同](SPRITE_ANIMATION_QA.md) §2.1 执行：**先有动作分析、逐帧分镜与真实帧数 N，再由 AI 每次生成一张包含多个连续姿势的 Sprite Sheet**。每帧设计姿势、承重、重心、武器或徒手打击轨迹与相邻变化；世界移动单独记录，不作为图像位移。N 由动作需要决定，不固定 6/8 帧。以角色事先选定的 **328×256 或 384×288** 作为单格制作容量，仅由 N 和一次生成的画布容量选择 C×R，不能为填满网格复制帧。全动作使用相同批准模型、100 源像素/米、地线与逻辑根点 O；生成的每格保持固定 O，不能逐格居中。**源 Sheet 必须按预设 W×H/C×R 机械拆格，逐格验证真 Alpha、至少 8px 透明边距、无越格、未用格透明和 N 个有效帧**；失败应回源修正姿势或重新生成，不能靠放宽格子或逐帧缩小放行。生图接口没有直接设置格数的字段，`C/R` 先写入提示词，生成后在候选 Resource 和导入器里作为结构化配置；视频提帧尚未真实验收，脚点工具不能识别真实承重脚或动作帧语义；循环/复位/攻击衔接继续实速预览。

**图集布局**：允许一动作一张或多动作共用一张，必须维护 `action_id -> ordered absolute frame_indices` 映射，并保留相同锚点和统一格宽高；图集格子数量不能决定各动作帧数。

**硬门槛**：每格有效 Alpha 与四边保留可验证的正透明边距，任何相邻动作帧内容重叠、越格、未用格有残留均自动拒绝；格子不足须选用高个档并重新生成，或回源重生成；更大规格须显式申报。断剑/断袖、额外武器、镜头变化、错误受力姿势必须优先重绘，不能靠裁切或提高 FPS 修好。人工只处理 AI/程序无法可靠确认的异常与最终少量样片；没有真正执行的 Godot 验收不能宣称完成。

## 4. Godot 原生导入方式

1. 候选原始帧/Atlas 留在 `art-production/candidates/`；Godot Art Production 导入工具以类型、拥有者 ID、语义文件名复制到 `res://assets/imported/`。此目录就是当前游戏资源区，不再划分 candidate/in_use 子目录；候选目录不能作为运行时入口。
2. 使用 `data/templates/actor_animation_profile.tres` 或角色已有 `WuxiaActorAnimationProfile`，配置动作 ID、Atlas、列/行、统一脚点、**局部视觉偏移**、逐帧时长及有序帧索引；可按需给某个 Clip 指定独立 Atlas。真实世界位移由战斗移动系统管理，不能直接复制离线 `root_offset` 到 Clip。动作和 VFX Cue 时序由原生配置描述，规则结算仍由战斗层负责。
3. 在对应 `WuxiaCharacterDefinition` 的 `animation_profile` 属性引用该 Resource。正式角色仍需在 `data/content_manifest.tres` 注册；**无需修改 `BattleModel` 或按角色 ID 添加脚本分支**。
4. 场景制作使用 `WuxiaSceneArtProfile` 管理同画布 `background`、`ground` 与可选 `foreground`、`weather`、`story_preview`，挂到战斗地图或剧情章节的 `scene_art`。空的图片属性优先按 `assets/imported/scenes/<scene-id>/<layer>.<ext>` 精确解析（仅要求已声明配置所需的素材）；显式指定的纹理始终优先。地图几何由 Map Resource 决定，缺少必需素材报错。正式场景同时交付可编辑分层母版。
5. 导入后预览完整动作；检查角色脚点、根运动、四攻击变体、倒地停留、VFX 有效帧。新动作不能依赖旧 Profile 的隐式动作回退；正式素材引用不允许暗中替换为占位图。
6. 导入并保存 Resource 后，该素材即成为对应槽位的当前使用版本；先预检变化、保留旧文件和 .tres 事务备份，需版本化替换时明确选择。技术接入不代表视觉及权属审核通过，结果记录在工作单中，不增加管理状态。

## 5. 各类素材的原生交付合同

| 资产类别 | 可交付格式 | 必需的技术条件 | 原生绑定 |
| --- | --- | --- | --- |
| 角色立绘 | 透明 PNG / WebP | 真实 Alpha、单人、身份一致、边缘完整 | `WuxiaCharacterDefinition.portrait` |
| 角色动画 | 透明 RGBA Atlas（PNG / WebP），可单动作或多动作合图 | 新制作为普通档 328×256／高个档 384×288 单格、人物设定身高×100 源像素，列行整除、逐动作有序帧索引、零越界、统一逻辑根点；运行时 12 组动作 ID 与显式 Clip 映射 | `WuxiaActorAnimationProfile` |
| 场景分层 | 同画布背景与透明图层 | 1600×1000 同原点；背景、独立 ground 必需，前景和天气按需 | `WuxiaSceneArtProfile` → Map 或 ChapterScene |
| 战斗 VFX | 透明 RGBA 图集或单图 | 真实 Alpha；列行可整除；`frame_indices` 不越界，按事件持续时间非循环播放 | `WuxiaVFXDefinition` 的 VFX/动作 Cue 绑定（亦支持原生 PackedScene） |
| UI / 卡画 | SVG / PNG / WebP 分件 | 文字与交互不烘焙进贴图；九宫格、裁切与小尺寸可读性人工验证 | Godot `Control` / 原生资产引用 |

- **兼容边界**：旧 6×4/256×256 等图集和单张背景仍按已绑定 Resource 运行，不批量改图或强行迁移；新人物帧按角色选用 328×256 或 384×288，列行及帧号由动画 Profile 解释，特殊规格须显式声明。
- **脚点语义**：动画播放使用 `WuxiaActorAnimationProfile.feet_offset`（Sprite2D 像素偏移）与 `actor_scale`；旧资产登记里的归一化 `foot_anchor` 仅为兼容元数据，不能与 `feet_offset` 混算。剧情与战斗必须优先使用同一 Profile。
- **自动校验不等于批准**：纹理可解码、Alpha、整除、索引和 `.tres` 引用属于技术检查。帧间连续性、四方向身份、实际前景遮挡、UI 手感和授权仍需人工审核。
- **规格状态**：新角色源图 **普通档 328×256／高个档 384×288、100 源像素/米、人物 100–220px** 已确定；动作 FPS、VFX 图集格子、UI 图标母版和色板尚待试点。**运行时 80 世界像素/单位、默认 200px 高及 24px 地面占位**目前保持不变，真实身高显示仍需另行迁移与验收。

## 6. 制作顺序与验收门槛

**试点：一名主角 + 一名敌人 + 一张战场 + 一张剧情场景**。先完成全流程，再批量制作其他人物和章节；现有角色绑定与故事资料不删除。

| 阶段 | 产物 | 退出条件 |
| --- | --- | --- |
| 风格锁定 | 角色设定、场景构图、色板和参考 | 身份/镜头/脚点一致 |
| 制作候选 | 透明角色素材、场景分层、动作关键帧 | 来源明确、规格可校验 |
| Godot 接入 | `.tres` AnimationProfile/场景/资产引用 | Import、动作、地图和导出加载通过 |
| 视觉审核 | 两套分辨率截图、动作录像、授权记录 | 记录品质／权属结论；不新增状态目录 |

历史雨夜断桥整图与沈长风概念图仅用于风格与后续拆层，不等同于可直接替换地图拓扑或逐帧动画的成品；制作稿按资产身份保存在 `art-production/candidates/`，不按日期建新目录。
