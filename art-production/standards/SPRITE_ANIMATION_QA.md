# 精灵动画生产与验收合同（逐帧 / 视频 / 3D 渲染统一适用）

本合同适用于《长风浮生录》全部战斗角色，而不是沈长风或某个 Demo。主规范为 [ART_PRODUCTION_STANDARD.md](ART_PRODUCTION_STANDARD.md)，生成提示词见 [ART_STYLE_AI_PROMPTS_V1.md](../prompts/ART_STYLE_AI_PROMPTS_V1.md)，最终动作编辑真源见 [《Godot 原生内容开发规范 V2》](../../docs/GODOT_NATIVE_AUTHORING_STANDARD.md)。这里定义制作、返工和验收流程，不新增 JSON 运行时格式或素材管理状态。

## 0. 当前证据等级与默认路线（优先于工具建议）

- **默认采用 AI 5×5 混合动作 Sheet**：先按角色设定身高换算 `100 源像素/米`（自然站姿人物 100–220px），角色事先选定普通档 **328×256px** 或高个档 **384×288px**。各动作先独立分镜、确定真实帧数 N，然后**按动作顺序跨动作、跨批次顺延装入固定 5 列×5 行、25 格**；一格仅绘制一帧。普通档一张标准化 Sheet **1640×1280px**，高个例外 **1920×1440px**。AI 不保证输出尺寸，先验 5×5 逻辑布局，后由工具处理尺寸和拆格。
- **逐动作 GIF 作为独立来源**：每个动作一张透明 GIF、每帧使用该角色已选的完整 W×H 画布；没有 C×R 网格，不经过 5×5 混合动作拆格。仍强制检查身份／武器、源身高、Alpha、至少 8px 边距、统一根点、真实时长和动作连续性；最终在 Godot `SpriteFrames` 面板编辑而非用 GIF 文件作为运行时动画真源。
- **视频转精灵图尚未通过真实素材验收**：PR #109 的提帧、抠图、打包流程仅是候选工具链；不能依赖它保持人物身份、推断动作帧或产生合格间帧，不作为本规范必经步骤。
- **脚点编辑器未验证可自动识别真实支撑脚、动作阶段或根位移**：当前只把它视为人工点击标记/原像素平移/图集装配辅助工具。任何自动 Alpha 下沿点、继承上帧点和自动排布都不能证明真实接触正确。
- **规则不等于能力**：AI 生成提示词尽量减少错误，但不能保证数值、帧间身份和力学自动正确；客观几何必须自动验收，AI 视觉只能初筛，无法确认的内容保留候选。没有有效的原始帧，不得进入对齐/补帧/导入。
- **提示词与验收分离**：生图只发送参考图、明确 5×5 行优先格位与多动作帧号、各格局部姿势、身份/武器与统一 O；**不把 328×256 或 1640×1280 当成模型可强制执行的像素参数**，不发世界位移或运行时 `root_offsets`。生成后机器测量原图，按可验证的格位、共同等比缩放与透明补边标准化，最后检查目标单格像素及 Alpha/边距。本合同的几何失败条件只用于预检，不塞进长提示词。

## 1. 已暴露的失败模式与返工判定

| 失败模式 | 常见症状 | 处理方式（禁止将失败伪装为通过） |
| --- | --- | --- |
| 身份 / 武器漂移 | 武器无故增加/丢失、握持突变、衣服或体型漂移 | 以该角色批准设定重新生成问题帧；核对武器契约、配色、头身比与允许的拔收/换手过渡 |
| 方向 / 镜头漂移 | 侧视变正视、镜头推拉、地线起伏 | 一个动作锁定视角、缩放、镜头和地面；重做偏离帧 |
| 运动不连续 | 关节扭曲、部件闪变、抖动、攻击收招突然后弹 | 先修关键姿势、运动轨迹与帧顺序，再补实际间帧；提高播放 FPS 不会创造动作 |
| 脚点误判 | 按透明轮廓最低点对齐，鞋底仍漂移 | 在分镜中先描述承重鞋底（倒地改用躯干接地），AI 初筛明显错误；疑难帧才人工核对，自动猜点不能证明真实支撑 |
| 根位移丢失 | 攻击前冲变原地踏步、动作后退瞬跳 | 分开记录局部姿态、逐帧接触点与根位移；不得把所有世界位移归零 |
| 源图截断 / 越格 | 武器末端、拳脚、发丝、鞋底缺失或侵入邻格 | 回源重绘或重生成完整帧；裁切、平移、扩画布不能恢复丢失的像素 |
| 图集挤压 / 比例漂移 | 每帧大小不同、横向拉伸、格间留白不足 | **AI 原始 Sheet 标准化阶段**只允许全批共同等比变换与透明补边；**标准化切帧后的最终 Atlas 打包阶段**保留目标格的原像素与统一 O，不再逐帧缩放、紧裁或居中。容纳不下须返工或申报例外 |
| Alpha / 视频闪烁 | 纯色底被误当透明、抠图边缘跳变、残影和模糊 | 检查真 RGBA、逐帧去背景与边缘；问题帧清理或重新提取 |
| 源 FPS 与运行时错位 | 24 FPS 标注但只有重复帧，或动作被压入旧时间窗口 | 记录真实采样和帧数；Godot 核对 AnimationProfile 与 BattleActionTimeline 的实际速度 |

硬失败：身份/武器错误、源帧缺画、关键发力阶段不合理、未复核脚点却声称稳定、严重闪烁/脚滑、错误图集索引。失败素材仍可留在 `candidate` 供比较，不得替换 `in_use`。

## 2. 生产之前冻结「身份 + 动作脚本」

1. 先确认同一角色的设定参考、主辅色、身形、鞋及 **`weapon_contract`**：有无武器、类型、件数、尺寸、持手/单双手握持、佩挂位置、是否允许拔收/换手。战斗小人只简化微细节，保留手绘武侠轮廓。**不允许在全角色规范中预设单手剑**；沈长风的右手直剑仅属于他自己的角色设定，其他角色可以单持、双持、双手握持或徒手。
2. 为每个动作先写 `起手 → 蓄力/承重 → 有效动作 → 收势` 的关键姿势分镜：身体重心、支撑脚、空脚位置、持握/出招肢体、武器或拳脚打击端轨迹、位移方向与接续姿势。让 AI 先输出少量独立关键姿势并自检一致性，再生成实际间帧；人工只处理异常和最终样片。**动作复杂度决定帧数，不规定 6/8 帧**。
3. 在生成提示词中**描述可见的力学姿态**而非只给动作名：idle 后脚承重；guard 按角色武器/徒手防御方式稳定承重；walk/run 前后脚交替落地（run 有腾空/快速换脚）；attack 按对应招式发力与换承重，不出现无理由的后退；evade 固定向后蹬地—腾挪—落地（方式由 `evade_style` 决定）；defeat 后期躯干接地。人工以画面判断承重是否成立，不强制每帧固定同一只脚。
4. 固定源镜头与比例。横版侧面动作使用严格侧视、静止摄像机和统一地线；前后方向要另做有效视觉资源，不能因为运行时镜像就宣称四方向完成。
5. 记录设定身高 `height_m`，目标自然站姿高度为 `round(height_m×100)` 源像素，只允许普通角色 **100–220px（1.0–2.2m）**。头顶至承重脚底为人物身高，举起的武器/头发衣摆飘动不能反向改变身高。整套动作同一角色选定 **328×256 或 384×288** 格、同一人物源像素比例与脚点；长兵器、巨型角色若无法满足，必须明确设计例外，不自动裁剪或压缩标准人物。

## 2.1 动作分镜的最小交付合同（AI 先规划）

- **先分镜、后生成混合动作多帧 Sheet**：每个动作独立规划实际 N、连续帧号、阶段和首尾合同，不能预设动作都 8 帧。分镜确定后按生产顺序填入固定 5×5 批次，允许相邻动作共享 Sheet，也允许动作跨两批续接，批次切口不能修改动作 N。参考 [AI 提示词 §5.1](../prompts/ART_STYLE_AI_PROMPTS_V1.md)；每批先记录 `batch_id/cell_index -> action_id/action_frame_index`。
- **按动作设计帧数**：先根据实际动作的起势、承重/蓄力、发力、有效姿势、惯性、收势、恢复划分事件；结合速度变化、脚步换承重、武器或拳脚打击轨迹的弧度和轮廓变化决定关键帧与真实间帧。帧数为有效逐帧清单的长度，不能以 6/8/12 或图集行列反推，不得复制重复帧凑数。短动作可少，复杂攻击可多；给出总帧数的动作依据，不冻结各动作帧数。
- **逐帧必填**：`frame_index`（从 0 连续编号）、`time_ms`（从 0 开始单调递增）、`phase`、`role`（key/inbetween）、`pose`（头、躯干、骨盆、四肢）、`support_contact`（承重脚/腾空/倒地躯干）、`center_of_mass`、`weapon_trajectory`（按 `weapon_contract` 记录武器位置/握持方式/方向；徒手记 `none` 并注明打击肢体轨迹）、`root_offset`（相对首帧）、`transition`（与相邻帧的具体变化）。标明建议总时长、是否循环、首末姿态如何衔接。
- **自动可核部分**：`frame_index` 连续且不重、每张 Sheet 中声明的有效格数与分镜子序列对应、全部有效非空格合计为 N、时间单调、字段完整、RGBA/边界/格间零重叠；AI 视觉只初筛动作重复、姿态跳变、角色武器异常、明显脚滑，不可据此声称识别真实承重脚或动作帧语义。AI 初筛不能通过时返工分镜或问题帧，只有疑难动作与少量最终样片人工查看。
- **时间语义**：`time_ms` 和阶段时长是离线分镜建议，不会自行生效；新动画将其显式写到 `SpriteFrames` 的 FPS／单帧 duration，旧 Atlas 才写到 `WuxiaActorAnimationClip.frame_durations`。Godot 依据对应帧时长比例铺满非循环动作的 `BattleActionTimeline` 表现窗口；不能用帧时长改变规则事件。长停顿／快爆发必须配置并实速验收。
- **攻击动画组**：每名角色从自己的 `weapon_contract` 设计四套独立攻击，`attack_thrust` 直刺、`attack_overhead` 下劈、`attack_sweep` 横斩、`attack_heavy` 蓄力重击只是单剑角色的分镜示例，不强制锤/枪/双持/徒手角色照搬。`combo` 指已有攻击的编排/衔接，不要求单独生成固定连携。正式 Godot Clip 使用已支持的 `attack1-4` 动作编号；完整 12 组须独立配置或明确绑定，不以旧 `attack/combo` 静默替代。

## 2.2 十二组生产动作与结束条件（P0）

美术生产按 **8 组通用动作 + 4 套角色专属攻击 = 12 组独立分镜** 组织；下表的四套攻击是**单剑角色示例**，其他武器依据角色设定替换对应攻击动作和语义 ID。每组独立编号、按动作实际复杂度定帧数并验收，再交给程序打包。

| action_id | 动作与必需阶段 | 首尾/复位合同 |
| --- | --- | --- |
| `idle` 待机 | 戒备、自然呼吸、衣摆细微惯性 | 循环；首尾姿势、接触和速度接近，不能多画重复闭合帧 |
| `walk` 行走 | 蹬地、摆腿、着地、换脚承重 | 完整步态循环；支持原地循环与外部移动，不可滑步 |
| `run` 跑步 | 前倾蹬地、摆臂、快速跨步、腾空/落地、换脚 | 完整跑步循环；频率与步幅明显区别于 walk |
| `attack_thrust` 直刺 | 屈膝蓄力、后脚蹬地、直线剑路、前脚接重、收剑 | 非循环；姿态归待机基准，允许合理前移 |
| `attack_overhead` 下劈 | 举剑、重心上提、沉肩下劈、缓冲收势 | 非循环；姿态归待机基准 |
| `attack_sweep` 横斩 | 腰胯预旋、支撑发力、水平剑路、惯性收势 | 非循环；姿态归待机基准，侧视不变正面 |
| `attack_heavy` 蓄力重击 | 沉身长蓄力、爆发踏步、重击、惯性缓冲 | 非循环；姿态归待机基准，不强迫同普通攻击帧数 |
| `skill` 技能 | 招式专属起手、蓄势、释放、命中反馈、恢复 | 非循环；按具体技能分镜，姿态归待机基准 |
| `evade` 闪避 | 向后蹬地、后撤腾挪、落脚、重建平衡；形式由 `evade_style` 选择 | 非循环；姿态归待机基准，保留向后位移 |
| `guard` 格挡 | 依据武器/徒手方式架挡或卸力、承受冲击、稳定、解除防御 | 非循环；撤架后归待机；持续格挡的保持态需单独说明 |
| `hit` 受击 | 受力后仰、移步缓冲、重新平衡 | 非循环；普通受击归待机，击倒改接 defeat |
| `defeat` 倒地 | 失衡、膝/躯干接地、落地惯性、静止 | **终止态例外**；保持倒地，不强行站起复位 |

- **统一身份与武器契约**：12 组使用同一获准侧视战斗基准模型和同一身高、镜头、服装、头身比及该角色自己的 `weapon_contract`。同一套装备外观动画中的武器数量、尺寸和握法不能随机变化；允许的双手转换、换手、拔收或徒手动作需要明确分镜过渡。若角色实际更换装备，应选择/制作对应的新动画候选或验证兼容，而非让原动画凭空变出另一种武器。不能把某一个角色的单剑设定套到其他角色。
- **闪避方向与方式**：`evade_direction=backward` 固定为相对角色当前面朝方向的**后撤**；`evade_style` 保留不同表现（`backstep` 后撤步〔默认〕、`slide` 后滑步、`roll` 后翻滚、`leap` 后跃）。不论选择哪种方式，分镜须有向后位移、落地承重和待机姿态复位；不能画成前冲、向敌人翻滚或瞬移回原地。世界位移仍按运行时实际控制能力验收。
- **结束条件**：idle/walk/run 是循环，验收循环接缝；其余除 defeat 外的非循环动作必须在动作结束时恢复**相对自身根节点的待机兼容姿势**（方向、上身、双臂、当前角色的武器/空手状态、平衡、承重），恢复姿态不代表世界位置回到起点。defeat 保持倒地静止。动作可接另一攻击，但衔接帧必须连续且可解释。
- **帧数自主规划**：每组按阶段时间、速度峰值、姿态跨度、武器或拳脚打击轨迹与承重切换选择不同帧数；不得给 12 组统一 8 帧，且不得用无变化重复帧填充网格。循环应闭合，非循环应检查从待机入招及收招回待机的过渡。

## 2.3 跨帧统一参考坐标系（P0）

- **固定逻辑系**：同一角色全套动作共享侧视、`100 源像素/米`、地线与右向基准。定义 `O=(0,0)` 为待机姿态的**逻辑地面根点**（骨盆在地面的投影），`+x` 向画面右侧、`+y` 向下。每格固定 **已选 328×256 或 384×288**，各格 O 的相对像素位置相同；整体 Sheet 可因 C/R 不同而长宽不同。不得以逐帧 Alpha bbox 中心重新定位或缩放角色，朝左须明确处理镜像与持手一致性。
- **双坐标记录**：`pose_local` 表示相对于角色逻辑根 O 的身体/武器局部姿势；分镜中的 `root_offset=(dx,dy)` **只记录计划中的世界位移**（相对动作首帧），不可直接复制进 `WuxiaActorAnimationClip.root_offsets`。后者按世界像素移动 Sprite2D 的**局部显示位置**，不移动战斗角色或碰撞体。分镜仍单独记录承重、触地和位移计划，供动作/地图控制器验收。
- **复位与世界位置分离**：普通非循环动作的局部姿态必须归待机；世界位移计划可保留正/负距离，由角色移动系统处理，**不要求世界位置回到起点**。但目前 Clip 校验明确要求普通非循环 `root_offsets` 的**末帧为 `(0,0)`**（`defeat` 例外）；不可把世界位移写入这个字段来绕过规则。原地 walk/run 帧图不烘焙整人位移，实际移动交给控制器；不能让图片与控制器重复消费同一段位移。
- **装配保持坐标**：单帧打包时每格保留对应 O 的固定像素锚点；计算全套局部姿势在此参考系下的联合非透明范围，确保连同每边至少 8px 安全边距**均能容纳在所选 W×H 中**，不能逐格紧裁切、单独居中或局部缩放。世界位移计划作为离线数据保留，不平移进帧图；跨动作共享 Atlas 时按同一根点对齐并记录有效帧索引。
- **当前运行时边界**：现有 `.tres` 只消费已显式填写的 `frame_durations`（逐帧时长）和 `root_offsets`（Sprite2D 局部视觉偏移）；**不自动读取**离线分镜/CSV 的世界位移计划。凡需真实世界前冲或后撤的动作，必须另由移动控制器/时间线明确实现与测试；AI 指令不能充当物理位移数据。

## 2.4 逐动作预检与打包交接（P0）

- **分组制作**：同角色 12 组各自保存完整分镜与真实 N，生图批次统一 **5×5 / 25 格**，按行优先顺序填写帧映射；示例首批 `walk[1..8]` + `run[1..8]` + `attack1[1..9]`，只有 `attack1` 的真实 N≥9 才这样安排；若只需 8 帧则第 25 格开始下一动作。跨批必须保存后续帧号，不能复制动作帧凑格；仅最后一批的尾部格允许全透明。记录原图实际尺寸、所选 W×H 和标准化后的 5W×5H，分组不以模型输出像素决定动作帧数。
- **布局验收→尺寸标准化→机械拆格**：先确认 AI 原图确实有可分离的 5×5 等格布局、真实 25 格姿势映射和同一 O，**不得仅凭 Alpha 聚类推断动作编号**；对所有格使用共同的等比变换与透明补边适配目标 328×256（高个例外 384×288），不能逐帧单独缩放、非等比拉伸、紧裁切或掩盖断裂。无法定位格子/保持完整轮廓和身高时返工。标准化后按 5W×5H 图集精确切 25 格，验证 RGBA、每边 ≥8px 留白、零侵占、尾部未用格透明；再按映射跨批还原每个动作第 1..N 帧进行实速连续性/循环/复位检查。
- **准入交接**：仅将通过每批 5×5 拆格与逐动作预检的原像素标准化切片交给打包程序，汇总各批 `batch_id/cell_index -> action_id/action_frame_index`；验证跨批不缺帧/错序/重复后装配成运行时 Atlas 和显式 `action_id -> ordered absolute frame_indices`。Godot 不自动识别源图中混合动作的分段；预检通过不等于画面已经验收或自动切换 in_use。
- **低人工成本**：默认自动格式/计数/几何检查和 AI 视觉初筛；真实承重脚与动作自然度无法被这些工具可靠证明，只有歧义、失败反复发生或最终少量样片需要人工复核，不要求逐帧手工标点。

## 3. 按来源选择生产路径

- **默认：AI 一张图输出一批 5×5 混合动作帧**：从已完成的动作分镜按顺序取至多 25 帧，先映射每格的动作 ID 与动作内帧号，使用获准角色身份/武器基准、固定镜头/O/脚点，每格一幅完整姿势。可以在同图接上下一动作，也可以让当前动作延续到下一张。画出 5×5 不能证明几何准确，原图必须通过布局检查、标准化及逐格验收。
- **实验性：视频 → 帧**：PR #109 尚未通过真实素材验收，不作为默认路线；即使可提取 MP4，仍不能识别真实支撑脚、动作语义或可靠生成间帧。用户明确试验时才用作 candidate，不能因为抽帧/抠图工具运行成功就宣称动画合格。
- **3D / 骨骼动画渲染 → 帧**：固定正交侧面相机、比例及光照，渲染独立透明帧；同样执行后续脚点、根运动、图集和 Godot 验收，不因模型有骨骼就跳过。

**生成时的优先级**：身份/角色武器契约 → 方向与比例 → 承重和动作意图 → 连续关键姿势 → 完整轮廓与留白 → 透明背景 → 最终图集。前面有硬失败就回到 AI 生成，不用后处理掩盖。

一次先做 `idle/walk/attack1/guard` 的美术试点，`attack1` 可按该角色的武器选择直刺等分镜；AI 初筛后，仅异常帧与最终样片需要人工复核，再批量制作其他角色。未完成所需 12 组动作时只作为阶段性候选，不冒充完整正式战斗 Profile。

## 4. 图集格子不重叠（P0 自动硬条件）

- **从源头保证**：AI 每次按固定 5×5 行优先输出多个动作的 25 个可分离姿势；整图分辨率不由生图提示词强制设定。普通档标准化输出 1640×1280（5×5 单格 328×256），高个档例外 1920×1440（单格 384×288）。每格人物符合设定 100px/米、真实 Alpha、完整轮廓及至少 8px 四边透明边距，无法分格或越格应返工。
- **程序拆格与排布**：先验证原始图 5×5 等格且人物/武器不混格，再使用同批共同**等比**缩放、透明补边将 25 格投射到同一 W×H 容器；必须保留统一 O、比例、地线，不能非等比拉伸、逐帧独立缩放/居中，不能裁去武器或修复已经缺失的画面。标准化结果尺寸必须恰好 5W×5H，方可程序定格切割。仅对通过 §2.4 的片段按动作/帧序组装；世界移动另存。
- **图集组织**：源 AI Sheet 固定 5×5，可有多个动作与跨批续帧；必须保留 `batch_id/cell_index` 到 `action_id/action_frame_index` 的确定性来源映射。最终可导出 `SpriteFrames.tres` 的逐动作帧序与时长，或用兼容 Atlas 的绝对帧索引；不能把混合源图直接绑定为单个 Clip。逐动作 GIF 不存在该 Sheet 映射，须保留自身帧号与来源。运行时支持 12 组动作 ID；旧名仅显式配置时兼容。
- **强制自动验收**：标准化后逐格检查 `left >= 8, top >= 8, right <= W-8, bottom <= H-8`（普通档右/下界 320/248；高个档 376/280）；宽高必须为 `5W×5H`，`cell_index` 0..24 唯一且与分镜帧号对应，只有末批尾部空格允许透明。原图无法可靠 5×5 分格、像素被裁切、非连续帧映射、变形缩放、越格/重叠均拒绝，不静默放宽。
- 自动几何验证能保证透明边距和格子隔离，不能判断人物身份、动作物理合理性或真实承重脚。

## 5. 脚点、根坐标与时间的独立合同

- **接触点**：生成时在提示词中说明支撑脚和地线，保持同一参考画布；AI 视觉可以初筛明显脚滑，但不能被视为可靠支撑脚检测。只有出现脚滑、换脚歧义或位移问题时才人工核对并可选标注。脚点编辑器不参与自动识别。
- **根位移**：在离线分镜以动作首帧为零记录世界位移计划 `root_dx, root_dy`，标明单位并与局部姿态分离。如视频工作流使用 `root_motion.csv`，单位是**源视频像素**，不是 Godot 世界像素；导入前必须按运行时视觉比例明确换算，且不得把整人位移同时写入 Sprite 图像和播放器偏移。相机移动不能当成角色根运动。
- **坐标转换**：原帧像素位置与世界 `CharacterBody` 位移是不同量。离线重排只改变画面内部位置；最终是否移动由 Godot 的现有移动控制和表现时间线处理。当前运行时**不会自动消费离线根位移 CSV/JSON**，不得宣称已经支持根运动驱动。
- **循环闭合**：生产时 idle/walk/run 分别检查末帧与首帧的姿势、接触、位移及停顿（新动画在 SpriteFrames 设循环，旧 Atlas 在 Clip 中设循环）；非循环动作检查每个阶段的速度和收势，不用相同静止帧充当补间。

## 6. 无损图集与当前 Godot 合同

1. **混合动作 5×5 Sheet** 须先通过布局、尺寸标准化及 §4 Alpha／间距／计数硬检，再按来源格位与动作内序号汇总，逐动作确认有效 N；合格切片可转换为原生 `SpriteFrames.tres`，或保持兼容的运行时 Atlas，分别检查帧序／索引并实速验收。[sprite-anchor-editor](../tools/SPRITE_ANCHOR_EDITOR.md) 仅辅助标注，不负责识别 25 格所属动作。**逐动作 GIF** 则核对每组原始帧完整画布、透明、时长和动作 ID，直接在 Native GIF Dock 预检并转 SpriteFrames，不需要虚构 5×5 来源格位。
2. 新角色仅选 **328×256 普通档**或 **384×288 高个档**，角色开工前选定；根据全部有效帧联合 Alpha 占用范围确定**是否能安全放入**，武器末端/拳脚、衣摆、头发、鞋底保留至少 **8px**、尽可能 **16px** 透明边距。超出时返工或明确记录特殊角色例外，不以裁切/逐帧缩放伪装合格。
3. **新原生动画**：`WuxiaActorAnimationProfile.native_frames` 引用 `SpriteFrames.tres`，动作名、顺序、逐帧时长、FPS 和循环在 SpriteFrames 编辑器维护；每动作 1..256 帧，`defeat` 非循环且保留终态。**旧 Atlas 兼容**：只有 `native_frames` 为空时才读取 Clip 的 `columns/rows=1..64`、绝对帧号、`frame_durations`，各动作可有独立图集；旧 6×4／每行 6 帧不是新标准。任何路径都不得使用未声明的动作隐式替代。
4. 旧 Atlas 的 `loop_fps` 和 `frame_durations` 定义帧节奏；新 SpriteFrames 用 `get_animation_speed`／`get_frame_duration` 对应的 Godot 编辑器字段。非循环动作均按 `BattleActionTimeline` 语义时长缩放。旧 Clip 的 `root_offsets` 是 Sprite2D 局部视觉偏移，**不是**世界移动；新动画的局部表现运动由 AnimationPlayer／现有表现控制器处理。离线视频 FPS、源图像素、CSV／JSON 不会自动改写战斗位置或规则。
5. **区分制作与运行时**：新源图按设定身高 `100 源像素/米` 绘制，普通角色人体 100–220px；当前 `combat_scale.gd` 仍为 80 世界像素/战斗单位、默认人物 200 世界像素、地面占位半径 24 世界像素。默认自动适配 200px 的播放器**尚不能按各角色设定身高在游戏中同比呈现**，实现时需显式配置和验证 Resource、导入器与世界比例；不能用 `Sprite2D.scale` / `feet_offset` 改伤害或判定距离。
6. 组装产物的 `frame_contract.json` 只是离线指导；导入器仍需显式配置／核对 `.tres`，不自动扫描 JSON。`ultimate` 等自定义动作必须有合法实际资源和显式事件绑定，不添加角色 ID 特判；不因已有可扩展动作名接口而自动宣称其美术已验收。

## 7. 从候选到使用中的质量闸门

以下 G0–G4 是**最终美术验收清单**，不要求在 V3 的加载、逐帧编辑或当前动作导入前全部通过。新制 AI Sheet 的生产验收与 V3 后加工操作分别适用。

**区分原始 AI 生产验收与 V3 后加工修复：**本文件对新生成的 5×5 AI Sheet、逐动作原始 GIF 的原始格位、身高及 Alpha 检查仍有效；已经存在的非规范原图可进入 V3 候选工作台逐帧修复，源图校验问题不直接阻断编辑。框选、颜色/Alpha 降噪、多边形和画笔修正、逐帧**等比**缩放与脚点位置微调只改变加工副本，最终输出使用两档画布，空帧和真实越界裁切仍阻断；≥8px 透明边距作为质量提示，不阻止当前动作导入和预览。角色自然身高、武器形状、动作连续性在实际 Godot 播放中检查。无论自动清理结果如何，源图缺损不算已被自动重绘。[流程与已知边界](../tools/FRAME_WORKBENCH_V3.md)。
