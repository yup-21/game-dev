# 精灵动画生产与验收合同（逐帧 / 视频 / 3D 渲染统一适用）

本合同适用于《长风浮生录》全部战斗角色，而不是沈长风或某个 Demo。主规范为 [ART_PRODUCTION_STANDARD.md](ART_PRODUCTION_STANDARD.md)，生成提示词见 [ART_STYLE_AI_PROMPTS_V1.md](../prompts/ART_STYLE_AI_PROMPTS_V1.md)，Godot 原生 `.tres` 与代码是运行时事实来源。这里定义制作、返工和验收流程，不新增 JSON 运行时格式或素材管理状态。

## 0. 当前证据等级与默认路线（优先于工具建议）

- **默认采用 AI 单次多帧 Sheet 生成**：先确定同一角色侧视基准、动作分镜和有效总帧数 N，再为**一组连续动作帧**选择 C 列、R 行、统一格子与透明间距；每次 AI 输出一张包含多个姿势的 RGBA Sprite Sheet，而非一次只生成一帧。程序依声明的格数机械切片和几何验收；AI 视觉仅初筛，无法语义识别动作帧或真实承重脚。
- **视频转精灵图尚未通过真实素材验收**：PR #109 的提帧、抠图、打包流程仅是候选工具链；不能依赖它保持人物身份、推断动作帧或产生合格间帧，不作为本规范必经步骤。
- **脚点编辑器未验证可自动识别真实支撑脚、动作阶段或根位移**：当前只把它视为人工点击标记/原像素平移/图集装配辅助工具。任何自动 Alpha 下沿点、继承上帧点和自动排布都不能证明真实接触正确。
- **规则不等于能力**：AI 生成提示词尽量减少错误，但不能保证数值、帧间身份和力学自动正确；客观几何必须自动验收，AI 视觉只能初筛，无法确认的内容保留候选。没有有效的原始帧，不得进入对齐/补帧/导入。

## 1. 已暴露的失败模式与返工判定

| 失败模式 | 常见症状 | 处理方式（禁止将失败伪装为通过） |
| --- | --- | --- |
| 身份 / 武器漂移 | 武器无故增加/丢失、握持突变、衣服或体型漂移 | 以该角色批准设定重新生成问题帧；核对武器契约、配色、头身比与允许的拔收/换手过渡 |
| 方向 / 镜头漂移 | 侧视变正视、镜头推拉、地线起伏 | 一个动作锁定视角、缩放、镜头和地面；重做偏离帧 |
| 运动不连续 | 关节扭曲、部件闪变、抖动、攻击收招突然后弹 | 先修关键姿势、运动轨迹与帧顺序，再补实际间帧；提高播放 FPS 不会创造动作 |
| 脚点误判 | 按透明轮廓最低点对齐，鞋底仍漂移 | 在分镜中先描述承重鞋底（倒地改用躯干接地），AI 初筛明显错误；疑难帧才人工核对，自动猜点不能证明真实支撑 |
| 根位移丢失 | 攻击前冲变原地踏步、动作后退瞬跳 | 分开记录局部姿态、逐帧接触点与根位移；不得把所有世界位移归零 |
| 源图截断 / 越格 | 武器末端、拳脚、发丝、鞋底缺失或侵入邻格 | 回源重绘或重生成完整帧；裁切、平移、扩画布不能恢复丢失的像素 |
| 图集挤压 / 比例漂移 | 每帧大小不同、横向拉伸、格间留白不足 | 单帧原像素无缩放打包，以所有帧最大轮廓确定共同格子与透明边距 |
| Alpha / 视频闪烁 | 纯色底被误当透明、抠图边缘跳变、残影和模糊 | 检查真 RGBA、逐帧去背景与边缘；问题帧清理或重新提取 |
| 源 FPS 与运行时错位 | 24 FPS 标注但只有重复帧，或动作被压入旧时间窗口 | 记录真实采样和帧数；Godot 核对 AnimationProfile 与 BattleActionTimeline 的实际速度 |

硬失败：身份/武器错误、源帧缺画、关键发力阶段不合理、未复核脚点却声称稳定、严重闪烁/脚滑、错误图集索引。失败素材仍可留在 `candidate` 供比较，不得替换 `in_use`。

## 2. 生产之前冻结「身份 + 动作脚本」

1. 先确认同一角色的设定参考、主辅色、身形、鞋及 **`weapon_contract`**：有无武器、类型、件数、尺寸、持手/单双手握持、佩挂位置、是否允许拔收/换手。战斗小人只简化微细节，保留手绘武侠轮廓。**不允许在全角色规范中预设单手剑**；沈长风的右手直剑仅属于他自己的角色设定，其他角色可以单持、双持、双手握持或徒手。
2. 为每个动作先写 `起手 → 蓄力/承重 → 有效动作 → 收势` 的关键姿势分镜：身体重心、支撑脚、空脚位置、持握/出招肢体、武器或拳脚打击端轨迹、位移方向与接续姿势。让 AI 先输出少量独立关键姿势并自检一致性，再生成实际间帧；人工只处理异常和最终样片。**动作复杂度决定帧数，不规定 6/8 帧**。
3. 在生成提示词中**描述可见的力学姿态**而非只给动作名：idle 后脚承重；guard 按角色武器/徒手防御方式稳定承重；walk/run 前后脚交替落地（run 有腾空/快速换脚）；attack 按对应招式发力与换承重，不出现无理由的后退；evade 固定向后蹬地—腾挪—落地（方式由 `evade_style` 决定）；defeat 后期躯干接地。人工以画面判断承重是否成立，不强制每帧固定同一只脚。
4. 固定源镜头与比例。横版侧面动作使用严格侧视、静止摄像机和统一地线；前后方向要另做有效视觉资源，不能因为运行时镜像就宣称四方向完成。

## 2.1 动作分镜的最小交付合同（AI 先规划）

- **先分镜、后生成多帧 Sheet**：AI 必须先交付独立于图像的动作分析、完整逐帧分镜和连续性审查；不能预设“画 8 帧”或让图集行列决定动作帧数。使用 [AI 提示词 §5.2](../prompts/ART_STYLE_AI_PROMPTS_V1.md) 先确定 N 和姿势顺序，再通过 §5.1 生成一张含连续多帧的 Sheet；模型无法稳定容纳完整 N 时，分成多个连续多帧时间段，保持全局编号。
- **按动作设计帧数**：先根据实际动作的起势、承重/蓄力、发力、有效姿势、惯性、收势、恢复划分事件；结合速度变化、脚步换承重、武器或拳脚打击轨迹的弧度和轮廓变化决定关键帧与真实间帧。帧数为有效逐帧清单的长度，不能以 6/8/12 或图集行列反推，不得复制重复帧凑数。短动作可少，复杂攻击可多；给出总帧数的动作依据，不冻结各动作帧数。
- **逐帧必填**：`frame_index`（从 0 连续编号）、`time_ms`（从 0 开始单调递增）、`phase`、`role`（key/inbetween）、`pose`（头、躯干、骨盆、四肢）、`support_contact`（承重脚/腾空/倒地躯干）、`center_of_mass`、`weapon_trajectory`（按 `weapon_contract` 记录武器位置/握持方式/方向；徒手记 `none` 并注明打击肢体轨迹）、`root_offset`（相对首帧）、`transition`（与相邻帧的具体变化）。标明建议总时长、是否循环、首末姿态如何衔接。
- **自动可核部分**：`frame_index` 连续且不重、每张 Sheet 中声明的有效格数与分镜子序列对应、全部有效非空格合计为 N、时间单调、字段完整、RGBA/边界/格间零重叠；AI 视觉只初筛动作重复、姿态跳变、角色武器异常、明显脚滑，不可据此声称识别真实承重脚或动作帧语义。AI 初筛不能通过时返工分镜或问题帧，只有疑难动作与少量最终样片人工查看。
- **时间语义**：`time_ms` 和阶段时长是**离线分镜建议**，不是 Godot 当前的逐帧时长 Resource；非循环动作仍均分到 `BattleActionTimeline` 的实际时长。若分镜需要明显的长停顿/快爆发，记录运行时节奏不匹配待办，不可声明设置 `loop_fps` 已解决。
- **攻击动画组**：每名角色从自己的 `weapon_contract` 设计四套独立攻击，具体 ID/打击方式可以因武器而不同；`attack_thrust` 直刺、`attack_overhead` 下劈、`attack_sweep` 横斩、`attack_heavy` 蓄力重击只是单剑角色的首批示例，不能要求锤/枪/双持/徒手角色一律做剑招。`combo` 指已有攻击的编排/衔接，不要求单独生成固定连携。每套均交付独立帧数和接续姿势。**现有运行时代码仍强制九动作含 `attack` 和 `combo`，并未识别上述四个新 ID**；变体只能先留候选，不可将其直接写成 clip.action 或借 `combo` 槽伪装已接入，运行时扩展另行实施。

## 2.2 十二组生产动作与结束条件（P0）

美术生产按 **8 组通用动作 + 4 套角色专属攻击 = 12 组独立分镜** 组织；下表的四套攻击是**单剑角色示例**，其他武器依据角色设定替换对应攻击动作和语义 ID。每组独立编号、按动作实际复杂度定帧数并验收，再交给程序打包。

| action_id | 动作与必需阶段 | 首尾/复位合同 |
| --- | --- | --- |
| `idle` 待机 | 戒备、自然呼吸、衣摆细微惯性 | 循环；首尾姿势、接触和速度接近，不能多画重复闭合帧 |
| `walk` 行走 | 蹬地、摆腿、着地、换脚承重 | 完整步态循环；支持原地循环与外部移动，不可滑步 |
| `run` 跑步 | 前倾蹬地、摆臂、快速跨步、腾空/落地、换脚 | 完整跑步循环；频率与步幅明显区别于 walk |
| `attack_thrust` 直刺 | 屈膝蓄力、后脚蹬地、直线剑路、前脚接重、收剑 | 非循环；姿态归待机基准，允许合理前移 |
| `attack_overhead` 下劈 | 举剑、重心上提、沉肩下劈、缓冲收势 | 非循环；姿态归待机基准 |
| `attack_sweep` 横斩 | 腰胯预旋、支撑发力、水平剑路、惯性收势 | 非循环；姿态归待机基准，侧视不变正面 |
| `attack_heavy` 蓄力重击 | 沉身长蓄力、爆发踏步、重击、惯性缓冲 | 非循环；姿态归待机基准，不强迫同普通攻击帧数 |
| `skill` 技能 | 招式专属起手、蓄势、释放、命中反馈、恢复 | 非循环；按具体技能分镜，姿态归待机基准 |
| `evade` 闪避 | 向后蹬地、后撤腾挪、落脚、重建平衡；形式由 `evade_style` 选择 | 非循环；姿态归待机基准，保留向后位移 |
| `guard` 格挡 | 依据武器/徒手方式架挡或卸力、承受冲击、稳定、解除防御 | 非循环；撤架后归待机；持续格挡的保持态需单独说明 |
| `hit` 受击 | 受力后仰、移步缓冲、重新平衡 | 非循环；普通受击归待机，击倒改接 defeat |
| `defeat` 倒地 | 失衡、膝/躯干接地、落地惯性、静止 | **终止态例外**；保持倒地，不强行站起复位 |

- **统一身份与武器契约**：12 组使用同一获准侧视战斗基准模型和同一身高、镜头、服装、头身比及该角色自己的 `weapon_contract`。同一套装备外观动画中的武器数量、尺寸和握法不能随机变化；允许的双手转换、换手、拔收或徒手动作需要明确分镜过渡。若角色实际更换装备，应选择/制作对应的新动画候选或验证兼容，而非让原动画凭空变出另一种武器。不能把某一个角色的单剑设定套到其他角色。
- **闪避方向与方式**：`evade_direction=backward` 固定为相对角色当前面朝方向的**后撤**；`evade_style` 保留不同表现（`backstep` 后撤步〔默认〕、`slide` 后滑步、`roll` 后翻滚、`leap` 后跃）。不论选择哪种方式，分镜须有向后位移、落地承重和待机姿态复位；不能画成前冲、向敌人翻滚或瞬移回原地。世界位移仍按运行时实际控制能力验收。
- **结束条件**：idle/walk/run 是循环，验收循环接缝；其余除 defeat 外的非循环动作必须在动作结束时恢复**相对自身根节点的待机兼容姿势**（方向、上身、双臂、当前角色的武器/空手状态、平衡、承重），恢复姿态不代表世界位置回到起点。defeat 保持倒地静止。动作可接另一攻击，但衔接帧必须连续且可解释。
- **帧数自主规划**：每组按阶段时间、速度峰值、姿态跨度、武器或拳脚打击轨迹与承重切换选择不同帧数；不得给 12 组统一 8 帧，且不得用无变化重复帧填充网格。循环应闭合，非循环应检查从待机入招及收招回待机的过渡。

## 2.3 跨帧统一参考坐标系（P0）

- **固定逻辑系**：同一角色全套动作共享侧视、源像素比例、地线与右向基准。定义 `O=(0,0)` 为标准待机姿态的**逻辑地面根点**（骨盆在地面的投影），`+x` 向画面右侧、`+y` 向下。源画布/图集可以有不同像素宽高，但各帧均使用从 O 推导的**同一个比例和锚点关系**；不得以逐帧 Alpha bbox 中心重新定位或缩放角色。朝左需明确处理镜像和武器持手一致性，不能在生成时随机翻转。
- **双坐标记录**：`pose_local` 表示相对于角色根的局部姿势，`root_offset=(dx,dy)` 表示该动作相对首帧的根运动（首帧为 0）。分镜须说明支撑/接触点在此坐标系的位置变化，标记需要离地的阶段。角色踏步前冲时保留真实 root_offset；从候选帧到图集不得通过逐帧居中将其抹掉。
- **复位与世界位置分离**：非循环复位指 `pose_local` 回到标准待机兼容姿势，**不要求 `root_offset` 回到零**。步行/跑步采用原地循环时，纹理根保持在 O 附近，实际世界位移交给控制器；若采用位移型循环，需有匹配的引擎根运动消费能力，否则暂作 candidate。不可同时把源帧位移烘焙进画面又让控制器重复移动同一距离。
- **装配保持坐标**：单帧打包时每格保留对应 O 的固定像素锚点；格子宽高取所有帧在此参考系下的联合非透明包围范围，再加四边安全边距，不能逐格紧裁切、单独居中或消除根位移。跨动作共享 Atlas 时也按同一根点对齐并记录每个动作各自的有效帧索引。
- **当前运行时边界**：Godot 现有 `.tres` 不会自动消费离线 root_offset/每帧时间表；凡需真实世界位移的动作，必须验证运行时移动与贴图运动的分工。坐标字段和 AI 指令只是生产合同，不能单凭提示词视为可自动识别的物理结果。

## 2.4 逐动作预检与打包交接（P0）

- **分组制作**：同一角色候选包按 `action_id` 保存分镜和 AI 直接生成的多帧 Sheet；记录动作真实总帧数 N、每张 Sheet 的 C/R、格宽高、时间段的起止帧号与行优先顺序。`C × R >= 当张有效帧数`，未使用格必须透明；不因格子容量复制静止帧凑数。
- **机械拆格与逐动作预检**：先按已声明的 C/R 边界切片，不调用自动语义分帧；逐格检测真 Alpha、四边透明边距、人物/武器/打击部位完整且未越格、非空格数量与总时序。只有通过后才将图集切片按帧序播放，检查身份/武器/侧视/比例、姿态与根位移连续性、循环接缝或末帧待机兼容复位（`defeat` 终止态例外）。AI 视觉初筛异常，失败时优先重生对应连续多帧片段；不能通过裁切修复缺失身体或武器。
- **准入交接**：仅将已通过 Sheet 格子与逐动作预检的原像素切片交给确定性打包工具；输出按 `action_id` 组织的真实帧数和有序绝对图集索引。打包后另做 §4 的零越格硬性检查和 Godot 运行预览。预检通过不代表已经通过完整动画视觉验收，也不自动将 candidate 切换成 in_use。
- **低人工成本**：默认自动格式/计数/几何检查和 AI 视觉初筛；真实承重脚与动作自然度无法被这些工具可靠证明，只有歧义、失败反复发生或最终少量样片需要人工复核，不要求逐帧手工标点。

## 3. 按来源选择生产路径

- **默认：AI 一张图输出一组连续动作帧**：以批准设定图、完整分镜及相邻姿势作为参考，指定动作 ID、N、C/R、每格共同基准 O、地线、人物比例及足够安全留白。每格只有一幅完整人物姿势，按行优先时序排列；必要时将长动作拆成多张连续多帧 Sheet。**AI 画出网格不代表网格合格**，必须程序化机械切分和逐格验收。
- **实验性：视频 → 帧**：PR #109 尚未通过真实素材验收，不作为默认路线；即使可提取 MP4，仍不能识别真实支撑脚、动作语义或可靠生成间帧。用户明确试验时才用作 candidate，不能因为抽帧/抠图工具运行成功就宣称动画合格。
- **3D / 骨骼动画渲染 → 帧**：固定正交侧面相机、比例及光照，渲染独立透明帧；同样执行后续脚点、根运动、图集和 Godot 验收，不因模型有骨骼就跳过。

**生成时的优先级**：身份/角色武器契约 → 方向与比例 → 承重和动作意图 → 连续关键姿势 → 完整轮廓与留白 → 透明背景 → 最终图集。前面有硬失败就回到 AI 生成，不用后处理掩盖。

一次先做 `idle/walk/attack_thrust/guard` 的美术试点（walk 和 attack_thrust 当前均未作为新运行时动作 ID 接入），AI 初筛后，仅异常帧与最终样片需要人工复核，再批量制作其他角色。未完成九动作时可作为预览候选，不能冒充完整正式战斗 Profile。

## 4. 图集格子不重叠（P0 自动硬条件）

- **从源头保证**：默认每次生成一张**多帧透明 Sprite Sheet**，按已选定 C×R 等尺寸格排放当前连续动作帧；每格仅一个完整姿势、所有有效 Alpha 位于所属格内部且四边有透明安全边距，不可跨格绘制武器/肢体、把人物挤成小图或改变参考比例。AI 无法可靠执行精确像素网格，任何越格、触边、缺画或错误帧数都必须拒绝并重新生成该动作/多帧片段。
- **程序拆格与排布**：先依预设 C/R 对 AI Sheet 作固定格子切分，检查尺寸整除、有效格数 N、空格透明及每格 Alpha bbox 与边界距离（m>0）；不要指望自动识别真正动作帧。仅对 §2.4 通过的切片按共享 O 锚点汇总姿势与合法 root_offset 的占用范围，预留最终共同格宽 W、格高 H 和边距后原像素装配；不能逐格缩放、紧裁切/居中或让相邻格共享像素。
- **图集组织可选**：允许一张 Atlas 只装一个动作，也允许同一角色的多个动作共用一张 Atlas；与动画质量无关，不强制每动作拆成一个 PNG。必须保存每个 action_id 对应的有序绝对帧索引、帧数、循环标志、首末衔接与统一格宽高；不允许帧索引错指、重复混用或把一个动作的关键帧误归另一动作。当前九动作运行时仍按原生 clip 枚举映射，新增 ID 保留候选。
- **强制自动验收**：对每个格逐格断言 `left >= m, top >= m, right <= W-m, bottom <= H-m`；图集宽高必须被列/行整除，所有索引合法，未使用格全透明。m 必须大于 0，24 源像素是推荐试点值而非固定单位。**任何一格越界、触边、与相邻帧非透明内容重叠，直接拒绝产物；自动扩大格子重排或回源生成，不能人工放行**。
- 自动几何验证能保证透明边距和格子隔离，不能判断人物身份、动作物理合理性或真实承重脚。

## 5. 脚点、根坐标与时间的独立合同

- **接触点**：生成时在提示词中说明支撑脚和地线，保持同一参考画布；AI 视觉可以初筛明显脚滑，但不能被视为可靠支撑脚检测。只有出现脚滑、换脚歧义或位移问题时才人工核对并可选标注。脚点编辑器不参与自动识别。
- **根位移**：记录角色骨盆/地面投影等一致的逻辑根参考，在该动作内以首帧为零记录 `root_dx, root_dy`。如视频工作流使用 `root_motion.csv`，单位是**源视频像素**，不是 Godot 世界像素。相机移动不能当成角色根运动；脚点锁定也不能抹掉冲刺距离。
- **坐标转换**：原帧像素位置与世界 `CharacterBody` 位移是不同量。离线重排只改变画面内部位置；最终是否移动由 Godot 的现有移动控制和表现时间线处理。当前运行时**不会自动消费离线根位移 CSV/JSON**，不得宣称已经支持根运动驱动。
- **循环闭合**：生产时 idle/walk/run 分别检查末帧与首帧的姿势、接触、位移及停顿（运行时当前仅 idle/move 是循环）；非循环动作检查每个阶段的速度和收势，不用相同静止帧充当补间。

## 6. 无损图集与当前 Godot 合同

1. **多帧 Sheet 先通过第 4 节的格子拆分/Alpha/间距/数量硬检以及逐动作视觉初筛**，再由确定性排布工具按原像素无损装配，并对最终 Atlas 重做逐格边距/隔离断言。[sprite-anchor-editor](../tools/SPRITE_ANCHOR_EDITOR.md) 只是可选的人工标注辅助，不承担动作、支撑脚或根位移识别。
2. 以全部有效帧的最大 Alpha 轮廓确定共同格子，武器末端/拳脚、衣摆、头发、鞋底都留透明边距。**24 源像素是试点建议值而非全局冻结数**；边距过小需调整格子，不能裁断角色。
3. 原生 `WuxiaActorAnimationProfile` 允许 `columns/rows=1..64`，总图集宽高必须整除列行；每个 `WuxiaActorAnimationClip` 使用真实绝对帧号，单动作 1..256 帧，当前九动作完整绑定且仅 idle/move 循环；walk/run/四攻击变体都是新美术生产 ID，在运行时新增映射前不得直接写入 clip.action。不要把旧 6×4/每行 6 帧当成新标准。
4. `loop_fps` 当前直接用于**循环**动画；attack/guard 等**非循环**动画帧会均匀分布到 `BattleActionTimeline` 提供的动作时长。视频来源 24 FPS 只是离线生产信息，尚不意味着运行时非循环动作也按 24 FPS 播放。
5. 视觉归一继续服从 `combat_scale.gd`：1 战斗单位 = 80 世界像素，普通人物可见高度 200 世界像素、地面占位半径 24 世界像素；不能以 `Sprite2D.scale` 或 `feet_offset` 修改攻击判定距离。改变格高后重新验脚底偏移，不沿用旧值盲调。
6. 组装产物的 `frame_contract.json` 只是离线指导；导入器仍需显式配置/核对 `.tres`，不自动扫描 JSON。任何自定义 `ultimate` 等新动作在运行时合同扩展前只当候选，不添加角色 ID 特判。

## 7. 从候选到使用中的质量闸门

| 闸门 | 检查内容 | 不通过怎么办 |
| --- | --- | --- |
| G0 设定 | 同一身份、武器数与手、姿势方向、风格 | 返工源参考或重画 |
| G1 多帧源 Sheet | 程序按预定 C/R 拆格，检查 N、Alpha、透明边距和零越格；AI 初筛身份/武器/侧视/连续性，异常再少量人工复核 | 重生成整个动作或受影响的连续多帧片段 |
| G2 几何 | **程序强制检查格子零重叠、无越界、透明边距、帧索引** | 格子不足则自动扩大重排；源图断剑则重生成 |
| G3 动态 | 12 组逐动作实速预览、首尾循环/复位、根位移/脚滑、武器轨迹、闪变及相邻攻击衔接 | 修正关键姿势、间帧与根数据 |
| G4 游戏 | 原生 Resource/帧索引、战斗时序/朝向、200px 视觉尺度，1600×1000 与 1440×900 GUI | 调整 `.tres` 或回源返工 |

提交候选时报告：角色及版本、提示词与关联 Resource、动作/帧数/FPS、逐格自动检查结果、异常帧、已完成的脚点/根位移复核、GIF/视频预览和 Godot 实测结果。只有 `candidate` / `in_use` 两个资产管理状态；验收证据与待解决项用工作单记录。技术通过不等于画面通过，未见实机效果不得宣称完成。
