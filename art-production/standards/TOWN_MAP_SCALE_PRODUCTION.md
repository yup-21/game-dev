# 城镇与大地图素材生成规范：统一世界比例尺（V1）

> 本规范是《长风浮生录》[美术合同](ART_PRODUCTION_STANDARD.md)的场景细则。适用于未来城镇、街道、山路、室内和战斗地形；规范的是**世界坐标、人物尺度和拼接流程**，不限制场景题材和手绘风格。
>
> **尺度唯一来源：** `demos/changfeng-battle/scripts/combat_scale.gd`，不准在提示词、导入器、地图里重新定义第二套固定常量。以下数值反映当前合同；修改时必须以 Godot 常量和回归验证为准。

## 1. 什么才叫同一比例尺

| 对象 | 项目统一值 | 在 1600×1000 单屏中的感受 |
| --- | --- | --- |
| 世界长度 | **1 u = 80 Godot 世界像素** | 20u 宽 × 12.5u 高 |
| 普通角色可见站立高度 | **2.5u = 200px** | 角色约占完整画面高度的 20% |
| 地面碰撞半径 | **0.3u = 24px** | 脚下占位，不把衣摆/刀剑当障碍 |
| 基础屏幕 | **1600×1000（16:10）** | Godot 渲染可缩放到窗口，世界坐标不随窗口缩放 |
| 场景图层 | **1:1 的世界像素** | 背景、地面、遮挡共享像素原点与尺寸 |

**源图与游戏比例的区分：** 新角色美术源图按设定身高 `100 源像素/米`、普通档 328×256／高个档 384×288（宽×高）制作；本篇的 **200 世界像素**是当前运行时 `auto_fit_height` 的显示基准，不代表每名角色已按真实米数显示。迁移前场景构图与人物显示仍以本篇运行时值校准，不修改 80px/u、碰撞或攻击距离。

**“世界像素”不同于玩家显示器上的物理像素。** 屏幕从 1600×1000 缩到 1440×900 时，人物、街道和门洞一起被缩放，世界坐标仍为原值。

- 同一可行走平面上，近景街面、门、NPC、主角采用统一比例。人物在地面上前后走动，**不因 y 坐标变化而自动缩小**。
- 远处山体、城墙天际线可以有绘画透视和层次，不以其“看起来的高度”决定战斗碰撞与移动距离。
- **地图画面不能靠把整张 PNG 再缩小或拉伸来塞进窗口。** 新地图原生 Resource 必须标记 `pixels_per_unit=80`，图片运行时 `image_scale=1`、`rotation_degrees=0`；地面碰撞与画面在同一坐标中编辑。
- 历史画面若源尺寸不完全一致，应以独立候选重新校准后迁移；不在本次规范修改中强行重采样旧素材。
- 对于大画布，80px/u 依然有效。**1600×1000 是单屏视口基准，不是所有地图图层的强制大小**；已接入的长街可用 1600×2000／2400 等真实世界画布，由 `WuxiaChapterSceneDefinition.world_size`、`WuxiaSceneArtProfile.reference_size` 或 Map 世界尺寸显式对齐并配合镜头跟随。不能把长图缩成单屏，也不能误认为已支持无缝城市、自动分块加载或跨区拓扑。

## 2. 借鉴 DNF 的画面密度（不是 DNF 官方像素数据）

参考《地下城与勇士》的横向街道、清楚的角色主体、相邻 NPC/入口和可选择区域地图。**本节数值是本项目自己的设计建议，不是声称测得 DNF 的精确尺寸。** 不复制其原场景或素材。

| 类型 | 本项目建议范围 | 对应世界尺度 | 目的 |
| --- | --- | --- | --- |
| 单屏城镇街区 | 1600×1000 | 20u × 12.5u | 现有引擎可直接生产、预览 |
| 主要可走街道带纵深 | 280–400px | 3.5–5u | 支持人物前后错位，不留无意义大空地 |
| 同平面门洞可见高度 | 256–304px | 3.2–3.8u | 比 200px 人物略高，门能合理通过 |
| 门洞可见净宽 | 120–180px | 1.5–2.25u | 以可见门框和交互口作为构图锚点 |
| 相邻可互动点水平距离 | 240–480px | 3–6u | 一屏内自然看到若干有意义的目标 |
| 单屏主要可互动目标 | 3–5 个 | 人物、门店、告示、入口等 | 不靠大批随机碎物堆积内容 |
| 单屏地标立面 | 1–3 处 | 店铺、屋檐、门坊等 | 街巷紧凑、易辨方向 |

上述区间属于**布局建议**，不作为 Godot 导入器的硬性拒绝条件。狭窄小巷、广场、桥头、客栈内景可以突破建议值，但玩家应在当前视野里很快找到行动方向。

**避免空洞的首要原则：** 不用“扩大 PNG 画布 / 缩小角色”表现城镇面积；使用可辨地标、前后遮挡、NPC、交互物与**多个街区连接**。一幅景里实质互动点很少时，宁可把画面缩成一屏，也不要留下几屏无目的空地。

### 2.1 横向、竖向与混合街区（同一世界尺度）

DNF 风格的城镇不是只能左右行走：角色也可以在地图地面上**向上、向下**移动。我们将街区的视觉主轴定义为以下三类；这是**地图美术布局与出口方向信息**，不会修改角色大小、碰撞半径、战斗计费、地形采样密度，也不改变窗口纵横比。

| 街区主轴 | 场景视角与移动 | 建议可走空间 | 连接出口 |
| --- | --- | --- | --- |
| `horizontal` 横向街道 | 主方向左右，路面允许前后走位 | 主街地面带深 280–400px | east / west，可按需向 north / south 支路 |
| `vertical` 南北街巷 | **主方向上下**，左右仍可躲避、绕开店铺与行人 | 中间一条宽约 240–400px 的纵向可走廊道，纵向贯穿 640–800px；必要时加侧向凹室 | north / south，可向 east / west 开侧门 |
| `mixed` 十字街口/广场 | X/Y 双轴可自由行走或拐弯 | 纵向路廊与横向街道交汇，交叉处必须完整连通 | 四方向组合 |

以上宽度是**建议的内容密度**，不是导入器强制像素约束。**屏幕始终横向 1600×1000**，竖向单屏可在该画布内绘制上/下贯穿的道路；需要连续纵向滚屏时，将世界画布扩展为 **1600×2000/2400** 等实际完整尺寸，由镜头显示 1600×1000 子区域。不可制作 1000×1600 后旋转，也不能将长图压缩回一屏。

### 全游戏统一视角：近似正交的 2.5D 轻俯视

**可走地面的投影优先于远景的美术透视。** 正式街区统一使用固定相机、轻俯视、以平行投影为主的弱透视画法：能同时看见人物站立所需地面和沿街店铺立面，但不能把南北方向实际可行走道路画成通向消失点的逐渐缩小的通道。不要为了露出更多屋顶而变成小比例俯瞰模型，也不要为了画出宏大街景而改成接近平视的单点透视。

- **世界坐标与人物比例不变**：正视建筑和屋檐只属于画面表达；无论角色沿世界 Y 轴走到哪里，同一普通人物仍以 200 世界像素高度绘制，不随远近缩放。
- **同一可走面的地面宽度稳定**：设计上 240–400px 的南北通行净宽，应在近、远两端仍能容纳 24px 地面占位半径的人物。可将视觉通行带近端/远端宽度偏差约 10% 以内作为构图自检建议，**不是用 AI 输出替代碰撞/地图几何测量**。
- **三层透视职责不同**：实际可走路面、店门、桥面与出入口属于弱透视游戏平面；远处城楼、河岸、天际线可以绘出更强纵深，但必须在不可走背景，不得让角色在视觉上走入缩小的远景道路。
- **四向街口特别要求**：横向道路必须连续到左右画布边、纵向廊道必须连续到上下边并真正交汇。供观赏的前景桥、水岸或屋檐不得截断已约定的出口路线。
- **同城相邻图一致**：平江府等同一城镇的区域保持相近建筑立面/屋顶可见比例、地面石板纹理大小、门洞尺度、光源方向与地面倾斜感。角色/门洞量尺通过 `scene_scale_guide.py` 核对，不使用模糊的相机角度文字替代实际像素校准。

视角比选案例：`PJ-02` 十字路口候选中，较高的轻俯视便于四向可走连接，但屋顶占画面过大时有微缩模型感；接近平视的牌坊街景更有沉浸感，但中央道路向消失点明显收窄、前景桥水也可能阻断横向出口。正式方向取**前者的可玩几何 + 后者的建筑立面比例与材质氛围**，保持弱透视，不直接复制任一图的透视错误。参见 `art-production/candidates/scenes/pingjiang_crossroads/CAMERA_REVIEW.md`。

**纵向镜头重点：** 保持 2.5D 横版动作 RPG 的斜俯视地面；纵向街巷不是上帝视角，也不是透视极强、远处人物变小的长街照片。道路在远近两端都按同一 80px/u 校准，前景房檐遮挡、近景建筑侧墙与左右门头按脚点和遮挡层组织。**人物走向画面深处仍是 200px 高**；地图宽窄不改变角色碰撞半径 24px；地面实际通行净宽应容纳该占位、NPC 和避让。

**镜头与资源边界：** 单屏横向／纵向／混合街区可直接使用；同一区域超出 1600×1000 时，战斗与剧情场景可使用 **1600×2400 等真实世界尺寸的图层 + 二维镜头跟随**，不把大图压缩成单屏，也不改变 UI 画布。玩家在纵向路廊移动时背景和角色整体滚动，脚点与鼠标目标使用相同的逆向坐标换算。前/后行走仍须补充完整方向动画；区域间传送、城市拓扑导航与超大图片的按需流式加载**尚未开发**。

### 2.2 竖向比例尺参考图

```bash
# 横向主街
python art-production/tools/scene_scale_guide.py --orientation horizontal --output /tmp/town_horizontal.png
# 南北纵向街巷（默认 300px 纵廊；同时绘制远、近两名等高角色参照）
python art-production/tools/scene_scale_guide.py --orientation vertical --output /tmp/town_vertical.png
# 十字路口
python art-production/tools/scene_scale_guide.py --orientation mixed --output /tmp/town_crossroads.png
```

三种引导图都从同一 `combat_scale.gd` 读取 80px/u、200px 人物高度、24px 地面占位。纵向引导图明确标出顶端 north 与底端 south 的出口，并用两名不同 Y 位置的**同高人物**防止 AI 将远处的路人缩小。可通过 `--lane-left / --lane-right / --lane-top / --lane-bottom` 调整道路廊道，但不准缩放标准人物来适配路宽。

## 3. 城市结构：区域图，不是一张巨型贴图

建议先采用**单屏街区 → 出口切换 → 下一个单屏**的制作单位；也可以把少数重要长街做成 **1–3 屏高的单个真实尺寸世界**，使用已接入的镜头跟随。真正的自动跨区切换、分块加载和世界地图导航需在后续独立实现。

示例城镇（拓扑示意，既有横向街道，也有纵向街巷与十字路口；不是现成游戏地图）：

```
                           北街（纵向）
                              │
城门驿路 ── 主街店铺 ── 十字街口 ── 河埠码头
              │               │
           客栈内景       南市街（纵向）
                              │
                           衙门正门
```

- 小型驿镇：**3–5 个单屏街区**；中型城镇：**5–9 个**；大型城池：先设计**区域/城区之间的拓扑**，再分批做街区，不规定必须一次生产完整城区。
- 城市“大”首先体现在区域数量、人物关系、功能和连通性，不等于屏幕上表现出真实城市的每一栋房子。
- 街区出口可设在**上/下/左/右**边缘或明确的门洞／道路交汇点；上下分别对应 north/south、左右为 west/east；进出两侧的**地面高度、建筑延续、光照、朝向和单位标尺**相匹配。
- 城门外墙、远景楼群等不可进入的空间是背景层，可以展示城市纵深，但不要成为巨大的不可行走前景空地。
- 全局地图/城市总览只展示拓扑和区域名，**不作为角色可行走的高分辨率底图**。

## 4. 图像生成前必须做的“尺度锁定”

1. **先绘制可走区域和关键交互点：** 选择 `horizontal` / `vertical` / `mixed`，设定本街区 1600×1000、脚点坐标、主街地面带或纵向廊道宽度、上下／左右出口、门洞位置、镜头、遮挡/通道；不是先让 AI 随机画一座城市再猜碰撞。
2. **生成透明比例尺参照层：** 在仓库根目录执行（竖向及十字参考见第 2.2 节）：

   ```bash
   python art-production/tools/scene_scale_guide.py --output /tmp/town_zone_scale.png
   ```

   此参考 PNG 有 80px 单位格、**200px 角色轮廓**、**24px 脚下占位**、**280px 门洞示意**和可走地面带。它是给画师/生成模型的构图控制图，**不能导入最终运行图、也不能烘焙格线**。
3. **生成分层同画布贴图：** 参考层和角色设定图作为视觉输入，先画 background/ground，再生成 foreground/weather，保持同一像素原点。先生成 1600×1000 的候选，重绘的不同街区都重复引用**同一模板和尺度图**。
4. **几何校准：** 在合成图中把身高 200px 的测试人物放到门洞旁、街道近端/远端，检查门洞、台阶与招牌是否持续合理。检查前后移动时足底是否始终在可走区域内，室内门洞是否真正能进入。
5. **接入原生 Resource：** `WuxiaSceneArtProfile` 的全部图层必须同画布；可玩战斗区走 `WuxiaMapDefinition` 原生地面多边形与障碍。城镇的区域切换、NPC 活动和章节剧情仍需后续独立的区域连接系统，不能指望单张地图导入器自动生成。
6. **逐区验收与扩建：** 先在 1600×1000 单屏完成“主角—门洞—NPC—街面”验证，再增加相邻区。保留已正确绑定的候选，不重复加素材来源表；来源仅需生成提示词及使用该素材的 Resource。

**验收会失败的情况：** 把 4800px 场景整体缩放到 1600px 再让角色站进去；把 200px 角色画成相邻房门的一半高后又让游戏把人物缩小；地面/背景/遮挡不同画布；美术引导贴图留在最终素材里；素材基准角色按 y 位置忽大忽小；地图采用非 1:1 运行时放缩或旋转却没有同步调整几何。

## 5. 城镇场景生成正向提示词（复制时填入变量）

```text
原创中国武侠 2D 城镇游戏背景，固定 2.5D 横屏斜俯视视角（街道主方向：{horizontal/vertical/mixed}），
精致简练的国风手绘，非3D建模，非低分辨率像素图。
街区：[区域名称 / 场景功能]；时间天气：[...]; 地标：[...].
输出为 1600x1000 单屏构图，世界坐标与输出像素 1:1 对齐，
世界标尺 1 战斗单位 = 80 世界像素。参考给定的透明比例尺引导层
和同一角色设定：测试人物站立可见高度 2.5 单位 = 200 像素，
门洞净高约 3.2–3.8 单位（256–304 像素），
横向街道可走地面带深 3.5–5 单位（280–400 像素）；
如果是 vertical，改为宽 3–5 单位（240–400 像素）的纵向可走廊道，
连通画面上方 north 和下方 south 出口；
如果是 mixed，纵向与横向道路在十字交汇处畅通。
人物参照与门洞在同一可走平面上，不随远近改变角色比例；
优先安排 3–5 个清晰互动锚点，避免无意义的大量空地。
画面背景和中景立面密度高，角色活动区清楚，无复杂透视变形。
各层保持相同相机、地平线、空间锚点和画布原点。
生成层：[background / ground / foreground]，其他层不混入。
仅输出场景画作，不包含实际人物、比例尺格线、测试假人、文字或 UI。
```

**反向约束：** 一整座城市在单张超大地图上、缩小所有角色塞进地图、门洞比人物矮、人物走到后方自动缩成一半、夸张透视、房屋与地面比例矛盾、不可行走区域占满中心、无交互目标的巨大广场、图层错位、道路与障碍关系不明、投影到 3D 格子底图、背景里残留参考尺、人物影子或 UI。

**多街区连续生成附加词：**

```text
本图是 [zone_id]，前一个街区 [previous_zone_id] 的连接出口在画布 [上/下/左/右] 边；
下一街区 [next_zone_id] 的入口在相反一侧，形成 north↔south 或 east↔west 对应。
不得把上一幅 1600x1000 图片旋转 90 度伪装成竖向区域。
严格复用已批准街区的 80 世界像素/单位和 200px 人物参照，
让连接的两条街面高度、地面材质、建筑檐口及光线延续，
连接区域留出清晰可走的道路；不得重新构图缩放前一张素材。
```

## 6. 常见坑和边界

- **AI 不是 CAD：** 即使提示词写上 80px/u，也无法保证每根柱子、门框和砖纹的精确几何。只有锁定引导层、后处理检查和 Godot 预览才能守住一致性。
- **视觉比例与逻辑占位不同：** 人物 200px 高，不等于需要直径 200px 的碰撞圆；现在 24px 是**水平地面占位半径**，地图上道路碰撞需要据此留空。
- **城市不需要物理真实尺寸：** 采用游戏化压缩，角色行走少、目的地明确；“步行距离”是游戏逻辑单位，不做历史建筑实际米数的伪精确换算。
- **1:1 图片是最终交付约束，不是 AI 原始输出限制：** 图像可以先在更高采样率生成，但需按统一全图比例重采样、局部修复和重新核对所有可走地面；不允许只拉伸单栋楼来迎合示意。
- **地图 Resource 支持**横向／纵向／混合布局标注及四向 `zone_exit` 目标区/入口元数据；`MapBake` 保存标记，FREE 路径沿 X/Y 移动。**同一区域连续上下/左右滚屏已支持**，但它不是自动跨区：超大图片切块加载、各城区入口转换和世界地图连接仍属后续工程。


### 2.3 纵向长街：1600×2400 世界画布，不改变屏幕比例

以下是**同一街区内连续移动和镜头跟随**的制作规格，不是多区域无缝接缝：

1. 输出背景、ground、foreground、weather（如需）**每层 1600×2400**，真实 Alpha 和完全相同的左上角原点；禁止将 1600×1000 旧背景拉伸到 1600×2400。
2. 剧情地图在 `WuxiaChapterSceneDefinition.world_size = Vector2i(1600,2400)`，`player_bounds`、NPC 坐标和主角脚点都使用完整世界坐标；`WuxiaSceneArtProfile.reference_size` 同样填写 1600×2400。剧情 UI 窗口仍是 1600×1000。
3. 战斗地图在 `WuxiaMapDefinition.viewport_size = Vector2i(1600,2400)`，原生多边形 `area_bounds`、walkable_outline、障碍与 NPC 坐标必须覆盖真实纵向范围；`scene_art.reference_size` 为 1600×2400。
4. **镜头跟随人物，不缩放人物**。上下移动的页面滚动只改变屏幕偏移，角色 200px 高、地面占位 24px 半径、移动/攻击的 80px/u 均不变。鼠标和触摸点需由屏幕坐标转换回世界脚点后判断碰撞。
5. 纵向长街的交通组织仍遵循紧凑街区原则，沿纵向每隔约一屏安排交互节点与方向提示；不能在两屏之间塞纯空路来凑城市规模。
6. 用下面的命令生成 1600×2400 的统一参考图（比例尺仍从 Godot 唯一常量读取）：

```bash
python art-production/tools/scene_scale_guide.py --orientation vertical --width 1600 --height 2400 --foot-x 800 --foot-y 1270 --lane-left 650 --lane-right 950 --lane-top 120 --lane-bottom 2320 --output /tmp/vertical_long_street.png
```

当前已提供的是**静态完整画布的镜头跟随**，而不是分块渲染/纹理流送。超过单个场景的巨型城市仍应拆成多个区域，避免显存与资源加载增长失控。

## 7. 纵向地图不得使用消失点透视（PJ-01 试点补充）

长幅纵向地图最容易出现的错误是：AI 把 1600×2000 的世界画布理解为摄影机沿道路向远方看去的**一张竖幅风景照**。因此画面上方的道路、石桥、建筑和门洞被缩成远景，而游戏角色与碰撞仍在全图保持 1:1。只写“弱透视”不足以解决这个问题。

**固定投影合同**：可走地面使用正交/平行投影的固定仿射关系，禁止带消失点的透视除法；背景层的远山、天空可单独作景深绘画，但不能决定世界地面宽度。Godot 的世界地面脚点与贴图仍按同一 XY 像素坐标放置，Camera2D 沿 Y 轴跟随仅改变画面偏移，不改变 zoom 或人物比例。

1. **先锁几何，再生图**：明确 north/south 端口、可走多边形、桥面、门洞和水域。以 PJ-01 为例，规划参考为 `1600×2000`、中轴 `x=800`、廊道左右边 `x=620/980`（规划宽 360px）。在可玩全程 `x_left(y)` / `x_right(y)` 应保持常数，而不是向画布上端收束。
2. **固定物体尺寸**：同种铺路石的 X/Y 周期、门框净高、桥栏厚度和人物站立 200px 参照在任意 Y 位置一致。左右建筑可画屋顶和侧立面，但不能越往上越小。高墙或檐口如遮挡主角，应成为独立前景层。
3. **生成顺序**：先创建无文字的等宽几何参考图，再以参考图为布局输入生成手绘候选；另一张现有场景仅提供材质、色板和光照参考。AI 输出后不要自动认为尺寸达标，必须在原分辨率叠加几何线复核。不能靠把最终整图横向拉宽、按 Y 透视纠偏来补救单个物体失真。
4. **两屏验收**：将完整长图按 `1600×1000` 视窗检查上、下两屏；每隔约 400px 比对等宽道路边、固定 200px 人物、24px 脚点及 256–304px 门洞。实机 Camera2D 上下滚动时，角色始终 200px 高且脚点不漂移。任何收窄使道路小于声明的可走净宽，或者建筑沿 Y 无故缩放，都判为候选待修正，不能接入正式 Resource。
5. **独立尺寸与状态**：规划的可走走廊（如 360px）不等于 AI 母版中目测的铺石带宽；只有人工对位、地面多边形及遮挡层全部通过，才可把图导入 `assets/imported/`。未通过的整图只保留在 candidate，不能通过强行缩放角色或隐式替换背景来掩饰。

复用的 PJ-01 等宽构图参考：[`art-production/guides/pingjiang_south_gate_parallel_1600x2000.svg`](../guides/pingjiang_south_gate_parallel_1600x2000.svg)。其他纵向场景可复制这一正交构图方法，但应按自身地图明确门洞、桥和通道尺寸，不照抄 PJ-01 的地标布局。
