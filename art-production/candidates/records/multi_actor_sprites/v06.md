## 批量生成（候选）

在仓库根目录运行：

```bash
python -m pip install Pillow
python art-production/tools/test_batch_anchor_align.py
python art-production/tools/batch_anchor_align.py --all
```

每个角色输出至 `art-production/candidates/characters/<actor_id>/`：

- `sprite_<actor_id>_atlas_anchor_v06.png`：不缩放、不裁断已有可见内容的 6×4 RGBA Atlas，格尺寸根据最大动作与 24px 边距自动确定。
- `preview_<actor_id>_<action>.gif`：九类动作逐项播放（**只是现有关键帧的循环预览，并非新增间帧**）。
- `<actor_id>.csv`：逐帧固定点、是否复核、根位移和源格贴边告警。
- `frame_review.json`：机器可读的边距、帧号和未验收列表，仅供离线审核。

无论跑几次，脚本都只写上述候选目录；**不修改** `data/native/animations/*.tres`、`assets/imported/in-use` 或运行时代码。

## 逐帧复核与再打包

1. 打开 PR #103 的 `art-production/tools/sprite-anchor-editor.html`，导入每名角色原始 `aligned_v03` 图集。按动作实际 `6×4` 切分。
2. 逐帧人工确认承重鞋底或躯干触地位置，确认不是衣摆、刀尖、影子；移动中的支撑脚交替，攻击的重心与根运动单独检查。
3. 把导出的各动作 CSV 合并到每人 `<actor_id>.csv`，使用 `action`（九类名称）、`frame`（该动作从 0 开始的局部帧号）、`x,y`（原始格内像素）和 `reviewed=1`。脚本另接受 `atlas_index`（6×4 中的绝对帧号），但必须与 `action/frame` 一致。角色的特殊刀、扇、袖、暗器数量按人设单独检查。
4. 若动画确实发生根移动，可在已复核的行填写 `root_dx,root_dy`；默认均为 0，程序不会猜测人物位移。
5. 重新生成：

```bash
python art-production/tools/batch_anchor_align.py --all \
  --annotations art-production/candidates/characters --require-reviewed
```

人工复核前 `--require-reviewed` 应故意失败。第 0 格不同朝向的废弃帧不参与 23 帧复核门槛。

## 为什么不能直接宣布五人全动作已优化完成

生成的 `anchor_target` 数字一致，只意味着像素在固定点旁的位置一致；它不能判断支撑脚是否选对、身体是否往后跳、刀剑是否多出或少了一把、是否真实存在脚滑。已有两个/三个关键姿势无法通过“增加 FPS”变成高品质动画。因此这个 PR 是**可批量复现的第一阶段工程交付**，不是五人的最终美术验收。
