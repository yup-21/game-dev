# 角色动画逐帧工作台 V3（首轮实现）

入口：Godot 编辑器 → `角色动画 V3` Dock；旧 `Art Production`／`Native GIF` 入口暂时保留，用于其他素材与旧资源兼容。正式资源仍以 `SpriteFrames.tres` 为动画帧序、FPS、循环与时长的唯一真源。

## 从 GIF 或精灵图导入一个动作

1. 选择**角色**和**一个目标动作**，选择本地 GIF、PNG、WebP 或 JPG。点击“载入并自动登记候选”。原图被哈希命名并复制到对应角色的 `art-production/candidates/characters/<id>/workbench/`；候选 `.tres` 自动建立，源文件不改写、不进入 Manifest。
2. **GIF**：自动解码所有帧和原时长，不强制输入固定 GIF 画布。**图片／精灵图**：输入实际行列点击“按当前网格切割并追加帧”，或点击“框选新帧”后在原图上拖拽任意矩形。可以追加不同来源的帧，并在帧列表中移动次序、删除空帧。
3. 选中任意帧即可使用矩形微调、描边多边形、点选脚点、擦除／恢复画笔、半透明阈值和背景清除容差。自动清理采用**Alpha 降噪、保守的边界颜色洪泛和孤立小区域清理**；不是可靠的语义人物分割，复杂背景与真实互相遮挡仍需人工修复／重制。
4. 点击“自动统一缩放”使用该动作帧集合的**共同等比倍率**。在标准输出画布上拖拽人物定位、滚轮调整当前帧等比缩放、方向键做 1px 微调。最终画布普通档 328×256，高个档 384×288，统一地面原点位于画布底边上 16px；四边仍校验至少 8px 真实透明边距。编辑器内数字参数是精调辅助。
5. 播放／暂停当前动作，设置每帧毫秒数、动作 FPS 与循环。点击“检查标准化成品”后，完成必要的视觉与来源／权属审核并勾选批准，再确认更新正式角色的**当前一个动作**。其他已存在的 SpriteFrames 动作继续保留，输出使用独立版本化路径。可撤销该次 Resource 事务；旧 PNG 保留可追溯。

## 输出与安全边界

- 源图没有 8px 边距、Alpha 不干净、原始分辨率不对，都**不是导入前硬错误**。抠图和统一尺寸完成后，对最终输出强制检查空帧、画布外溢和 ≥8px 真透明边距。
- 当前版本会在编辑器内保存并使用原生 `SpriteFrames.tres`。整动作需 1–256 帧，标准动作 ID 为 `idle/walk/run/attack1-4/skill/evade/guard/hit/defeat`。缺少其他动作不阻断当前动作制作；但新角色需要先存在原生 `idle`，否则不会擅自丢弃旧版 Clip 动作。
- `SpriteFrames` 原生修改受到版本化保护，不覆盖已存在的版本资源；导入时保留确认、内容哈希、事务备份及回滚。
- 每个角色的正式 `AnimationProfile` 必须是独立的外部 `.tres`；工具会先保存并重新加载它，再把该资源引用写回角色。连续导入 `idle → walk → run` 应始终累积在同一角色**当前版本**的 `SpriteFrames` 中，而非把 Profile 内嵌到 Character 或把某次动作覆盖掉。
- **已有错误数据不自动兼容/修复**：如果旧版 V3 已将 `data/native/characters/<id>.tres` 的 `animation_profile` 写成内嵌 SubResource，或其路径与 `data/native/animations/<id>.tres` 不一致，导入预检会报出实际/期望路径并停止。请先检查这两个 `.tres` 与对应 `SpriteFrames`，使用当次导入事务撤销或 Git 备份恢复到明确正确的引用关系，再重新导入；不要直接把异常内嵌数据猜测合并到正式资源。
- 正式 `in_use` 替换需要人工明确勾选视觉／来源权属批准。候选预检通过不等于美术批准。
- 与旧版相比，V3 允许对**制作后加工副本**进行明确的逐帧比例和偏移修正，但禁止非等比拉伸，也禁止用抠图伪造源图中缺失的人体／武器细节。每次动作应核对最终人物自然比例、脚点和动画连续性。

## 已知边界与下一轮改进

- 智能抠图目前依赖确定性的几何／颜色／Alpha 分析；复杂背景应使用画笔和多边形手工修正。未来可替换为专用语义前景分割模型，但不能把其成功率当作生产前提。
- 目前会话编辑参数保存在编辑器内存，来源候选永久留存；**编辑会话持久化、跨重启继续修帧、完整撤销重做和真正的拖拽缩略图排序**仍属后续工作。每次正式导入的最终帧与动作信息已持久化到原生 SpriteFrames。
- Godot GUI 的复杂描边性能、真实动画节奏和两种窗口布局须在与仓库匹配的 Godot 4.7 环境中人工验收；仅通过 4.6.3 headless 解析不能替代这一环节。
