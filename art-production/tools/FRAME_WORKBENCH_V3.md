# 角色动画逐帧工作台 V3（首轮实现）

入口：Godot 编辑器 → `角色动画 V3` Dock；旧 `Art Production`／`Native GIF` 入口暂时保留，用于其他素材与旧资源兼容。正式资源仍以 `SpriteFrames.tres` 为动画帧序、FPS、循环与时长的唯一真源。

## 从 GIF 或精灵图导入一个动作

1. 选择**角色**和**一个目标动作**，选择本地 GIF、PNG、WebP 或 JPG。点击“载入并自动登记候选”。原图被哈希命名并复制到对应角色的 `art-production/candidates/characters/<id>/workbench/`；候选 `.tres` 自动建立，源文件不改写、不进入 Manifest。
2. **GIF**：自动解码所有帧和原时长，不强制输入固定 GIF 画布。**图片／精灵图**：输入实际行列点击“按当前网格切割并追加帧”，或点击“框选新帧”后在原图上拖拽任意矩形。可以追加不同来源的帧，并在帧列表中移动次序、删除空帧。
3. 选中任意帧即可使用矩形微调、描边多边形、点选脚点、擦除／恢复画笔、半透明阈值和背景清除容差。自动清理采用**Alpha 降噪、保守的边界颜色洪泛和孤立小区域清理**；不是可靠的语义人物分割，复杂背景与真实互相遮挡仍需人工修复／重制。
4. 点击“自动统一缩放”使用该动作帧集合的**共同等比倍率**。在标准输出画布上拖拽人物定位、滚轮调整当前帧等比缩放、方向键做 1px 微调。最终画布普通档 328×256，高个档 384×288，统一地面原点位于画布底边上 16px；四边仍校验至少 8px 真实透明边距。编辑器内数字参数是精调辅助。
5. 播放／暂停当前动作，设置每帧毫秒数、动作 FPS 与循环。点击“检查标准化成品”后，工具会列出**本次自动创建/更新的全部依赖和路径**。点击“导入并绑定当前动作”，在最终确认窗口核对所选角色与动作即可执行。其他已存在动作继续保留，Resource 事务可以撤销。
6. 点击**「预览实际动画（已绑定 SpriteFrames）」**，无需再创建测试场景。弹窗读取当前角色已经保存并绑定的 `AnimationProfile.native_frames`，可选择所有已导入动作、播放／暂停和逐帧切换。默认按游戏角色显示比例及脚点展示；勾选“1:1 原始像素”可观察各动作真正的 Alpha 可见尺寸。此预览不读取尚未导入的工作台编辑帧。

## 自动创建依赖与操作提示

| 依赖 | 自动处理方式 |
| --- | --- |
| 源文件和候选记录 | 按哈希归档原图，生成 `WuxiaArtCandidateDefinition.tres`；不需要手动声明网格 |
| 动作图集 | 自动建目录、生成透明 PNG 与裁切帧 |
| SpriteFrames | 每个角色固定 `data/native/animations/<id>_frames.tres`；没有则新建，有则在同一文件中仅替换选中的动作，保留其他动作 |
| AnimationProfile | 没有则新建，有则使用当前配置，生成本角色外部 `.tres` 并绑定 SpriteFrames |
| Character 引用 | 自动更新当前选中角色的 `animation_profile`，不修改其他角色定义 |

导入前会显示这些生成/修改路径。即使当前没有 `idle`，也能先导入 `walk` 等动作；界面会提示缺少待机动画，但不会替用户猜测或制造假的动作帧。

## 输出与安全边界

- 源图没有 8px 边距、Alpha 不干净、原始分辨率不对，都**不是导入前硬错误**。抠图和统一尺寸完成后，对最终输出强制检查空帧、画布外溢和 ≥8px 真透明边距。
- 当前版本会在编辑器内保存并使用原生 `SpriteFrames.tres`。整动作需 1–256 帧，标准动作 ID 为 `idle/walk/run/attack1-4/skill/evade/guard/hit/defeat`。允许分批补齐动作，不要求先创建空白 Profile 或人为凑齐 12 组。
- 正式使用的 `SpriteFrames` 文件名不含版本号。重复导入同一角色时，写入同一个 `<id>_frames.tres`，并在写入前对该 `.tres` 做事务备份，可撤销恢复。原先已绑定的 `frames__版本号.tres` 只读取并作为历史文件留存，不再追加新的版本号文件；不擅自删除旧文件。
- 用户只需选择当前角色与动作；工具以该角色**当前读取到的动画内容**为起点生成新 SpriteFrames，并保存独立 AnimationProfile 后再引用回来。既有 Profile 是内嵌、共享，或没有单独的文件，都**不构成导入前置条件**。本次操作会将所选角色绑定到其自己的 `data/native/animations/<id>.tres`，不会直接改写其他角色的引用。
- 连续导入 `idle → walk → run` 时，每次继承该角色当前 SpriteFrames 的其他动作，不重新缩放或重写已存在动作的纹理。新动作的「自动统一缩放」以已绑定 `idle` 第一帧可见高度为参考（如存在），避免每个动作各自撑满单格而产生明显尺寸跳变；每帧仍可手动调整。导入器不诊断和清理历史错误数据，也不判断动作美术是否合格；完成后请用「预览实际动画」检查。发生文件写入错误时仍会回滚本次事务。
- 正式绑定前只有一次清楚列明路径的操作确认，不要求提前勾选“美术合格”。导入成功不代表视觉／来源权属已完成验收，使用者可在 Godot 中实际查看后再决定是否保留或撤销。
- 与旧版相比，V3 允许对**制作后加工副本**进行明确的逐帧比例和偏移修正，但禁止非等比拉伸，也禁止用抠图伪造源图中缺失的人体／武器细节。每次动作应核对最终人物自然比例、脚点和动画连续性。

## 已知边界与下一轮改进

- 智能抠图目前依赖确定性的几何／颜色／Alpha 分析；复杂背景应使用画笔和多边形手工修正。未来可替换为专用语义前景分割模型，但不能把其成功率当作生产前提。
- 目前会话编辑参数保存在编辑器内存，来源候选永久留存；**编辑会话持久化、跨重启继续修帧、完整撤销重做和真正的拖拽缩略图排序**仍属后续工作。每次正式导入的最终帧与动作信息已持久化到原生 SpriteFrames。
- Godot GUI 的复杂描边性能、真实动画节奏和两种窗口布局须在与仓库匹配的 Godot 4.7 环境中人工验收；仅通过 4.6.3 headless 解析不能替代这一环节。
