# 沈长风：原精灵帧 → 通用 Bone2D 逐帧临摹与验收

## 验证范围与来源

- 正式图集：`res://assets/imported/candidates/2026-11-01/shen_changfeng/sprite_shen_changfeng_atlas_normalized_v02.png`。
- Godot 动画资源 `data/native/animations/shen_changfeng.tres`：idle #1，move #2–5，attack #6–8，共 **8 张可辨认的目标帧**。
- 真正的统一 22 骨人体：`res://prototypes/humanoid_rig/humanoid_side_core.tscn`。本验证不使用之前的 V2 复合攻击贴图；头发/衣摆分别关闭，防止遮挡真实关节。
- 标注数据 `source_frame_landmarks_v1.json`：每帧保存头、颈、胸、骨盆、前后肩肘腕手、髋膝踝脚、部分可辨认的剑柄与剑尖。总共 166 个标注点（其中多个攻击腿部是推测点）。
- 坐标：把源图集每 256×256 格显示为相当于 470px 的参考网格，统一固定地面到游戏像素 `y=0`；世界脚点始终在 Godot `(800,730)`，不通过每帧缩放或拉伸让骨架假装贴合。

## 重要的数据可信度限制

实际原图 **attack #6–8 的靴子碎片与躯干脱开并悬空**；因此这三帧的腿、膝、踝、脚位置只能粗略推测，**不进入可靠关节平均误差**。#7/#8 长剑尖端在原图中也存在无法准确定位/握向冲突，不进入主体关节评分。部分 walk #5 的腿也被衣摆遮挡。不能宣称不可靠区域已经临摹成功。

源图几何关节是**视觉估计标注**，并非作者提供的独立 2D 动作姿势骨点，因此误差数值只用于**相对诊断**，不能当成生产美术的精确真值。

## 真正使用 Godot 骨骼进行匹配

- `source_frame_pose_trace.gd` 逐帧读取显式骨点，保留骨骼原始长度及层级，并采用从胸腰到肩肘腕、从骨盆到髋膝踝的逐级旋转拟合。仅允许骨盆相对固定世界脚点移位，不改变全局缩放或线性拉伸四肢。
- `source_frame_trace_overlay.gd` 在实际渲染场景中分别绘制**骨骼当前位置、源图目标标注、连线和残差**；剑柄/剑尖使用真实独立 Marker2D。
- `capture_shen_true_source_pose_trace.gd` 对每帧生成 **原始精灵图 / Godot 实际骨架叠加 / 纯骨架+标注** 三图；每帧计算平均/最大关节偏差，并输出 `joint-errors.json`。
- `tools/build_shen_true_trace_visuals.py` 组合待机、移动、攻击三张逐帧对照板及短 GIF；`visual-review-summary.json` 明确给出 **NOT_APPROVED**，而不是用 CI Success 代替视觉验收。

完整生成文件位于 `demos/changfeng-battle/captures/shen-rig-first/true-source-trace/`，并随 `unified-wuxia-hud-visual-evidence` CI artifact 上传。

## 下一次修改应基于误差，而不是继续主观编角度

最集中的偏差来自后肩和上身关节链：必须先重新确定**胸骨/肩骨的 Rest Pose 相对位置与上臂长度**。随后修正移动帧的后脚踝与快速步态、攻击第 #7 帧的前腕/握剑点。不要在这些结构不吻合时开始大批量绘制新分件 PNG。
