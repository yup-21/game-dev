# 《长风浮生录》美术与动画制作规范 V1

**适用范围：整个游戏，而非某个 Demo 场景。** 本规范同时约束角色、地图、剧情演出与战斗表现。Godot 原生 Resource 是游戏内容入口；源图和制作过程可以保留在概念素材区，但不能作为第二套运行时数据格式。

## 1. 美术方向与资产状态

- 中国武侠手绘、精细但简洁的轮廓、克制的水墨肌理和真实材质；HD-2D 描述固定镜头、纵深、前后景及遮挡，不强制像素画，也不使用 3D 棋盘叠图。
- 角色立绘与战斗小人属于同一身份设计：发型、服装配色、武器及标志性配件不得无故变化。
- 地图使用可阅读的地面空间，中央可行走区域与场景装饰分离；效果不得遮住重要站位、交锋目标或 CTB。
- `concept`/ `preview`：方向探索；`candidate`：技术检查通过但未人工批准；`runtime`：当前能被加载，不代表美术质量合格；`approved`：图像、动作、脚点、授权、GUI 全通过。
- 新候选必须保留来源、生成说明、修改记录与权属；**未经批准不可覆盖正式运行图**。`assets/production_manifest.json` 只属于离线审核，不是游戏内容入口。

## 2. 场景制作合同

- 以 **1600×1000 的 16:10 逻辑画面**做基础设计；同时检查 1440×900 窗口，不能依赖单张图天然填满所有裁剪尺寸。
- 每张正式场景的交付包包含 `background`（远景）、`ground`（可站立地面）、`foreground`（可遮挡主体）、可选 `weather`/光照遮罩。所有图层采用相同画布原点、尺寸和透明通道；保留可编辑母版。单张概念图不等于分层交付。
- 附带 Godot 原生 `WuxiaMapDefinition` / `WuxiaGridMapDefinition` 的地面、障碍、出生点、剧情标记。角色脚点与地图可行走区域在同一坐标空间，绝不根据 PNG 颜色推断碰撞。
- 固定摄像机比例、地平线和人物脚点参照；重要道具及前景遮挡另建 `Node2D` 层，避免贴死在背景而无法正确穿行。
- 雨、雾、流水、灯光和落叶均为可关闭的独立表现层；低性能档关闭后不影响路径、LOS 或脚点。
- 验收：六人可站立区足够清楚，路径/碰撞与画面一致，前景遮挡正确，分辨率截图和真实 GUI 试玩通过。

## 3. 角色制作合同

- 先冻结一张身份设定板：正/背/左右轮廓、主色/辅色、武器、脚底基点、动作态度。立绘、故事姿态、战斗 Atlas 用同一设定。
- 立绘为独立透明 PNG/WebP；动作图要求真实 Alpha、统一色彩和明确的脚底基点，禁用白底 JPEG 当作已批准图集。
- 一个 Atlas 内每格宽高一致且能整除图集宽高。**新内容不再要求固定 6×4**；旧 6×4 只作为兼容回退。所有动作的帧范围明确列在 `WuxiaActorAnimationProfile` 中。
- 最低动作集合：`idle`、`move`、`attack`、`guard`、`hit`、`evade`、`skill`、`combo`、`defeat`。非循环动作必须具备可辨识的起手/有效/收招，而不是只拉伸一个姿势。
- 朝向要求最终实现前、后、左、右一致的轮廓与脚点。目前播放器对左右使用镜像，上下仍沿用最后水平朝向；在完整方向动作接入前，不能把角色标为四方向最终批准。
- 游戏规则时序由 `BattleActionTimeline` 记录语义窗口；动画帧只负责表现，不能写 HP、Qi、CTB、背包或响应权。

## 4. Godot 原生导入方式

1. 在 `assets/characters/` 放置最终 Atlas、立绘；概念版本保持在 `assets/concepts/`，并记录制作来源。
2. 复制 `data/templates/actor_animation_profile.tres`，设定 Atlas、列/行、脚点偏移、缩放和每个动作的实际帧索引。循环动作按 `loop_fps` 播放；非循环动作由既有 `BattleActionTimeline` 控制完成时长。
3. 在对应 `WuxiaCharacterDefinition` 的 `animation_profile` 属性引用该 Resource。正式角色仍需在 `data/content_manifest.tres` 注册；**无需修改 `BattleModel` 或按角色 ID 添加脚本分支**。
4. 场景制作使用 `WuxiaSceneArtProfile` 引用同画布 `background`、`ground`、`foreground` 和可选 `weather`，并挂到 `WuxiaMapDefinition` 或 `WuxiaGridMapDefinition.scene_art`。地图几何仍由原 Map Resource 决定；未挂 Profile 的老地图继续显示单张背景。正式场景须同时交付可编辑分层母版。
5. 导入后预览完整动作；检查角色移动脚点不漂移、攻击方向正确、VFX 与有效帧对齐。未配置 Profile 的老角色保持旧 6×4 兼容播放。
6. 成品通过材质边缘、动作连续、成本/性能、资源依赖与授权审查之后，才进入 `approved`。

## 5. 制作顺序与验收门槛

**试点：一名主角 + 一名敌人 + 一张战场 + 一张剧情场景**。先完成全流程，再批量制作其他人物和章节；现有角色绑定与故事资料不删除。

| 阶段 | 产物 | 退出条件 |
| --- | --- | --- |
| 风格锁定 | 角色设定、场景构图、色板和参考 | 身份/镜头/脚点一致 |
| 制作候选 | 透明角色素材、场景分层、动作关键帧 | 来源明确、规格可校验 |
| Godot 接入 | `.tres` AnimationProfile/场景/资产引用 | Import、动作、地图和导出加载通过 |
| 人工批准 | 两套分辨率截图、动作录像、授权记录 | 批准后才替换当前运行素材 |

**本次 2026-11-01 候选**：`assets/concepts/2026-11-01/` 的雨夜断桥整图与沈长风全身概念，只用于定风格与后续拆层；它们不是可直接替换地图拓扑的成品，也不是逐帧动画。RPG、敌方 HUD 修改不包含在本轮。
